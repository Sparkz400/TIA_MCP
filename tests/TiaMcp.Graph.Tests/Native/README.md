# Native GRAPH qualification runner

This opt-in .NET Framework 4.8 runner requires installed TIA Portal V21 Openness. It is independent of the shared Host and native session. It creates each TIA process directly with `new TiaPortal`, creates a fresh `GraphScratch` project, and never attaches to a discovered process. Disposal applies only to instances it created. No CPU connection, download, online operation, or existing project is used.

```powershell
dotnet build tests/TiaMcp.Graph.Tests/Native/TiaMcp.Graph.Native.csproj
# The output directory must not exist. Keep its name short for TIA's path limit.
& tests/TiaMcp.Graph.Tests/Native/bin/Debug/net48/TiaMcp.Graph.Native.exe `
  tests/TiaMcp.Graph.Tests/fixtures/native-rich-seed.xml `
  tests/TiaMcp.Graph.Tests/Native/bin/my-run
```

The runner selects the newest installed catalog entry for CPU 1511-1 PN and records its exact type identifier. Evidence includes the seed and executable hashes, API assembly hashes, process/project ownership, compiler messages, archives and byte-original native exports. There is no automatic retry after an import failure. A failed run keeps its evidence and requires a new output directory for another run.

A successful run performs authored-seed import, software compile, save and native export; no-op import of that native export; compile/save/export; close and reopen in a newly created TIA process; and retrieve the saved checkpoint into a new directory in another newly created process. The document tests assess the exports separately. A successful runner exit alone does not establish preservation or arbitrary GRAPH compatibility.

The runtime project/archive files stay in this directory's ignored `bin` output. Reviewable fixture exports and receipts can be copied into `../fixtures/native-v21` after their independent expected content has been checked. An import seed is authored input, never labeled a native export. Embedded language bodies remain retained XML in the document package.


The captured qualification results and known native empty-module rejection are documented in [native evidence](../fixtures/native-v21/README.md). The minimal `native-seed.xml` intentionally reproduces that rejection; use `native-rich-seed.xml`, `native-populated-seed.xml`, `native-cross-sequence-seed.xml` or `native-alternative-seed.xml` for the completed profiles.

An optional third argument can identify this runner's own `before-import.zap21` from a previous run. The runner checks the archive hash against `baseline.json` and its project-ownership receipt, then retrieves it into the new run directory in a newly created process. It does not open or attach to the source project. This speeds fixture experiments while retaining process/project isolation.

`Collect-Evidence.ps1` copies byte-original exports and JSON receipts into a new named fixture profile, refusing to overwrite an existing profile. The manifest hashes every included file. Archives and executables stay in `bin`.

For diagnostic experiments only, a fourth argument `--probe-actions` tests eight predeclared action representations in separate GRAPH blocks in the new owned scratch. It records each import/compile outcome and exports only consistent blocks. Its `probeCompleted` result is not a native qualification result. Normal qualification never enters this mode.

`create_seeds.py` regenerates the authored parallel fixture from the minimal native seed and the original schema fixture. Native exports are never generated by that script. The other import seeds are retained as their own independently authored fixture inputs.
