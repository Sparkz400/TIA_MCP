# Native PLC type lifecycle fixture

These minimal, original SCL and UDT documents contain no native GUIDs or private library metadata. `CreateFromDocuments` generates the native identities inside a newly owned scratch project. Siemens documents these formats and the required STEP 7 target environment in [Creating new type from document](https://docs.tia.siemens.cloud/r/en-us/v21/tia-portal-openness-api-for-automation-of-engineering-workflows/tia-portal-openness-api/functions-on-libraries/creating-new-type-from-document).

Run `scripts/qualify_native_library_types.py` with explicit `--run-native`, immutable `--host` and `--worker` executable paths, and a short `--artifacts` directory. It uses the real MCP stdio harness and creates only owned headless TIA sessions and scratch projects. It never attaches to an existing process and performs no physical or simulated download.

The requested profile is creation and release of both types, native document export, publication/archive, selected-version consumption in a fresh project, FB edit/release as a second generation, explicit default selection, project update and fresh-reopen link verification. The second generation changes release metadata only; it does not claim behavioral or incompatible-interface migration coverage. Reports retain the exact first failure and all preceding native observations; an incomplete run never counts as qualified.

The negative update case requires an unreferenced FB and UDT to be rejected before mutation: Siemens' native update cleanup can delete unreferenced project objects even with unused-library-version deletion disabled. The positive case imports `ConsumerReferences.scl` through the existing source-change workflow. It retains the original scratch Main call and adds an actual FB instance call and a DB field of the library UDT, reachable from Main. It checks exact version links and native exports of unrelated blocks before and after updating. No runtime execution is implied.

For focused feedback after an implementation fix, `--authoring-baseline-report` can reuse a prior runner-owned initial-generation project. It requires intact prior creation/release/use/export evidence, reopens only that report's owned scratch path in a fresh portal, and revalidates exact native GUIDs, committed state and uses. It links the prior report and hash and leaves `freshAuthoringVerified` false. It starts a new global library and new changes; failed changes are never replayed. Omit this flag for a complete fresh authoring run.
