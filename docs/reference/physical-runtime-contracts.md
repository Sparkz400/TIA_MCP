# Physical runtime protocol contracts

The first part of [RT-01](../plans/expansion-plans/physical-plc-runtime.md) is implemented in `src/TiaMcp.Core/PhysicalRuntime/WebRuntimeProtocol.cs`. It is a pure request/response library: **no network connection, authenticated session, MCP runtime tool, capture loop or physical qualification is delivered by this increment**. That protocol-only baseline is now followed by the [initial owned Web session workflow](physical-runtime-sessions.md); the feature catalog is partial. Full RT-02/03 and the remaining plan are still required.

## Current behavior

`Context` canonicalizes a selected HTTPS controller origin and binds supplied connection ID, epoch and peer-certificate digest. `Validate` refuses noncanonical records; `SameContext` rejects endpoint, connection, epoch or certificate changes. These checks prove equality of supplied records only. A future trusted transport must obtain and verify the peer certificate before it constructs this record; neither a hash nor a supplied endpoint authenticates a CPU or downloaded program.

`Symbol` retains the exact supplied symbol spelling and representation (`simple` or `raw`) and hashes the supplied metadata with the existing canonical JSON helper. Name and datatype are required, duplicate properties refuse, and unknown metadata contributes to the hash. It does not synthesize a fully qualified symbol from a display name or claim that the metadata identifies the current program. The caller must retain the original metadata alongside this digest.

The only request constructors are `Discover`, `Browse` and `Read`. They emit `Api.Browse`, `Api.GetPermissions`, `PlcProgram.Browse` and `PlcProgram.Read`. There is no raw-method escape hatch. Browsing supports one explicit variable or immediate children; root browsing omits `var`, as documented. Recursive discovery, paging/storage and cross-symbol batching are not implemented here. [Siemens browse contract](https://docs.tia.siemens.cloud/r/simatic_s7_1500_et_200mp_manual_collection_dede_21/ubergreifende-informationen/funktionshandbucher-cpu/webserver/api-application-programming-interface/prozessdaten-lesen-und-schreiben/plcprogram.browse?contentId=Gg_E6goCyt80SaSYujf1CQ).

`Names` validates bounded method/permission lists. `ReadAvailability` distinguishes `unsupported`, `permissionUnknown`, `permissionDenied` and `permittedAtObservation`. These are observations, not durable authorization. A future session provider must refresh rights and still handle per-call denial. Discovery is not filtered by user rights; permission names are separately available from `Api.GetPermissions`. [Siemens method discovery](https://docs.tia.siemens.cloud/r/simatic_s7_1500_et_200mp_manual_collection_itit_20/comprehensive-information/cpu-function-manuals/web-server/api-application-programming-interface/web-api-basic-functions/api.browse), [permission discovery](https://docs.tia.siemens.cloud/r/simatic_s7_1500_et_200mp_manual_collection_enus_21/comprehensive-information/cpu-function-manuals/web-server/api-application-programming-interface/web-api-basic-functions/api.getpermissions?contentId=LcWSqRUoehRLDRh2eFzpbg).

`ReadResult` requires the same context and the exact read request, then checks JSON-RPC version, string request ID, one result/error branch and integer error code. It rejects duplicate JSON properties recursively, malformed UTF-8, oversized/deep documents and changed requests. Errors retain the numeric provider code and a fixed status, never the remote message/data. Successful values retain exact JSON representation, including 64-bit numbers, structured or currently uninterpreted types. `raw` results must be byte arrays. **`status: read` means protocol success; it does not validate a datatype conversion or sensor quality.** [Siemens read contract](https://docs.tia.siemens.cloud/r/simatic_s7_1500_et_200mp_manual_collection_enus_21/comprehensive-information/cpu-function-manuals/web-server/api-application-programming-interface/reading-and-writing-process-data/plcprogram.read?contentId=6rEaX6Ix8XQ2wNdmf08eVg).

## Result and limits

The [schema](../../contracts/physical-runtime.v1.schema.json) describes `physical-runtime-web-read.v1` results. It checks structure, not live target ownership. UTC request/receive times are distinct from monotonic elapsed duration. A backwards UTC adjustment is retained as `hostClockWentBackwards`; source/server timestamps are null. Atomicity, scan synchronization, device/program verification and native qualification remain false. An error cannot carry a previous good value.

Current contract limits: 256 KiB response, JSON depth 32, 64 KiB selected metadata/request validation, 2,048 method/permission names, 10,000 browse rows, 4,096-character symbols and 60 seconds maximum supplied read duration. These are defensive parser limits, not a scheduler, controller throughput budget, measured network timeout or Siemens quantity guarantee. The planned transport has a stricter per-request deadline and must enforce limits while streaming, before passing bytes to this parser.

## Verification and next work

`tests/TiaMcp.PhysicalRuntime.Tests` checks exact values, context/request tampering, response/error handling, metadata hashing, permissions and clock uncertainty. `scripts/test_physical_runtime_contracts.py` independently checks C# output against the schema and fixed numeric/time expectations. Both regular test runners include the suite and cross-check; hosted CI retains its result artifact. Current results are recorded in [the implementation evidence](../verification/physical-runtime-contracts-20261017.md).

The [initial owned Web session flow](physical-runtime-sessions.md) now supplies a trusted transport and protected credential consumer. Next: finish remaining RT-01/02 provider-neutral and route-profile contracts, the remaining [RT-03 capture](runtime-captures.md) fault/association/diagnostic checks, UA, diagnostics, cross-domain program association and separately gated actions. Existing inventory and simulator behavior remains separate. No supplied protocol result may satisfy a native acceptance gate.
