# Review supplied Project Server observations

`multiuser_observation_review(uploadRef)` accepts a committed UTF-8 JSON upload with schema `multiuser-observations.v1`, up to 4 MiB. It compares before/after declarations of one exact server host and port, retains the original bytes, and publishes an immutable content-addressed report. No Siemens product or endpoint is accessed. [Example](../../fixtures/multiuser/observations.json), [schema](../../contracts/multiuser-observations.v1.schema.json), [full X05 plan](../plans/expansion-plans/multiuser-project-server.md).

Each capture supplies an ID, exact UTC timestamp, producer, principal, server alias/host/port, and separate groups, projects, sessions and markings. Host is an HTTP/HTTPS/net.tcp authority URI without embedded port, credentials, path, query or fragment; port is a separate integer. URLs and names are retained exactly, not authenticated or canonicalized into native identities. Use public diagnostic text only; do not include passwords, session tokens or private configuration.

Each section declares `complete`, `partial`, `unknown`, `denied`, `failed` or `unavailable` coverage. Incomplete sections require a diagnostic. Only complete/partial sections may contain rows. An empty failed query remains failed; it never establishes an empty server. Project revisions are opaque nullable strings. Lock state is `locked`, `unlocked` or `unknown`; only locked has an owner. Session mode is `multiuser`, `exclusive` or `unknown`; `upToDate` is Boolean or unknown null. Mark-state strings remain exact declarations rather than a locally invented vendor enum.

Identity comparison uses exact group segments/project name, then session ID, then object path. It does not establish stable native identity across replacement, rename or reconnection. Missing parent declarations become explicit issues; no same-name repair or cross-snapshot object mapping occurs. Duplicate identities/JSON fields, unexpected fields, contradictory lock states, malformed text and changed host/port refuse. One capture ID cannot describe different snapshots within the same pair.

Changes distinguish `onlyBefore`, `onlyAfter` and `differentObservation`. These are supplied-row differences, not native creation/deletion or commit outcomes. Metadata, coverage and diagnostic changes remain visible. Every phase records that deleted-object markings are not represented; even complete empty markings cannot prove absence of conflicts. Unchanged markings and other rows remain in the paged observations section.

`multiuser_observation_page(recordId, section, offset, count)` reopens the retained record and rebuilds its report from the retained original input. Sections are `summary`, `observations`, `changes` and `issues`; pages contain 1..200 requested rows and fit within 128 KiB. Oversized rows have an explicit omission marker and remain available in the full artifact. `artifact_read` downloads original/report bytes by the returned references and hashes. Upload release and Host restart do not remove the retained source or repeat acquisition.

Bounds per capture: 128 groups, 256 projects, 512 sessions, 2,048 markings and 16 group-path segments. Exact text is bounded to 512 characters, paths to 4,096 and host to 2,048; malformed UTF-8/control text refuses. Reports are bounded to 32 MiB and retention to 512 MiB, including interrupted publication files. A capacity refusal does not authorize server work.

All source-authenticity, live-freshness, stable-project-identity, conflict-free, native-executable and native-qualified flags remain false. This workflow does not create/open/save/close sessions, acquire locks, mark/unmark, commit, delete or reconcile an engineering journal. Those native workflows and the remaining packages in the full plan remain open.
