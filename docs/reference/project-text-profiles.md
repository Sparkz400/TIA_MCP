# Project-text workbook profiles

The offline translation package is implemented in [TiaMcp.Translations](../../src/TiaMcp.Translations/TiaMcp.Translations.csproj). It accepts an **explicit unqualified cell map**. The initial implementation used synthetic workbooks; the later native export verification (`artifacts/expansion-foundation-20261015/native/translation-verification-02.json`) captures four genuine V21 legacy/object/category-selection exports from one owned scratch project, with the executed helper source and binaries retained. Their observed layout safely fits the existing read model. Import/empty-cell semantics and broader target formats remain unqualified. `synthetic` and `unqualified-explicit` remain the only accepted profile kinds; offline model flags for native qualification, execution and import permission remain false.

The [profile contract](../../contracts/translation-profile.v1.schema.json) maps an opaque native key and exact category to its key/source cells and explicit culture/target cells. Each location is an exact OPC worksheet path and A1 cell coordinate. Keys and locations must be unique; the actual key cell must match. The project uses the shared [engineering object reference](../../contracts/engineering-object-reference.v1.schema.json). The original workbook SHA-256, profile digest, project/snapshot/content identity and source/target state digests bind subsequent reviews. They describe captured evidence, not a native project freshness probe.

`TranslationWorkbook.Open(bytes, profile, project, expectedWorkbookSha256)` retains original bytes and exposes immutable observations. It rejects mismatching bytes, unsupported cell types, absent rows, malformed/duplicate keys/cells, ambiguous language mappings and foreign identity kinds. Missing target cells, explicit empty cells and text containing only whitespace are distinct. Shared and plain inline strings are readable; rich text is visible as rich text but cannot be edited by this slice. The supplied source/target culture names must be canonical .NET culture names; the native packet observes active `de-DE` and `en-GB` on that exact scratch project only.

Package checks cover ZIP central/local directory names, entry counts, sizes and CRC; duplicate entries; path traversal and escaped part paths; OPC content types and internal relationship targets; root/workbook/sheet relationships; XML DTD/entity refusal; formula and macro/active-content refusal. External relationships are rejected without fetching them. ZIP64, split/encrypted archives, non-UTF8/non-ASCII part names, nonstandard workbook locations and strict-OOXML variants are not supported by this profile. They remain explicit expansion/feasibility work rather than native impossibility claims. BCL APIs are sufficient; no Excel process, spreadsheet automation, Siemens code or network is used.

Defaults are 100 MiB compressed, 512 MiB expanded, 10,000 entries, one million cells, 32 MiB per XML part, one million XML reader nodes per part, depth 128 and 1,048,576 UTF-16 characters per text. Callers can lower limits; fixed ceilings are 128 MiB compressed, 512 MiB expanded, 10,000 entries, one million cells, 64 MiB per XML part, one million XML nodes, depth 128 and 1,048,576 text characters. The cell budget also limits mapped absent locations. JSON contract input is capped at 16 Mi characters and duplicate JSON keys are rejected. In-memory profile/edit snapshots copy immutable records and mutable collections without that JSON-input roundtrip; callers loading a larger external profile must still honor the JSON contract limit. These are implementation bounds, not Siemens limits or a resident-memory guarantee.

The 100k-key synthetic run (`artifacts/expansion-foundation-20261015/translations/evidence-02/scale-100k.json`) measures ten owner worksheets, four categories and two target cultures, full paged inspection, selective 1,000-cell review/write/reopen, independent preservation and timing/memory observations. Worksheet-row, native-key and selected-cell indexes avoid per-row whole-sheet scans. The package and XML model still live in memory; the measured process peak is retained explicitly. Production sizing, whole-project native scale, durable job integration and crash/recovery acceptance remain open.

An unchanged candidate is byte-for-byte the original ZIP. Changed candidates retain every unmodified OPC part's bytes. Edited XML preserves all unselected nodes semantically and retains nontext cell attributes; only selected cell string representation/content may change. Shared strings can become inline strings only when explicitly enabled in the offline profile. Other references to the shared string and the shared-string part stay unchanged. Rich strings, phonetic metadata or other opaque string/cell children or attributes block flattening. Opaque content elsewhere remains unchanged. Native acceptance of the conversion still requires a genuine layout and qualification.

Text decoding/encoding preserves exact Unicode without normalization, OOXML escaped controls, literal `_xHHHH_` sequences, CR/LF/tab and leading/trailing spaces. Invalid isolated UTF-16 surrogates are refused, including escaped surrogate values decoded during capture. Mapped duplicate string containers, duplicate shared-string indexes, mixed inline/shared encodings and mixed plain/rich text representations are rejected as ambiguous. `MaxUtf16Length` is an explicit profile limit; no native pixel/glyph/byte limit is guessed. The `brace-literals-v1` grammar compares exact literal brace tokens and multiplicity, permitting reordered tokens. It is a synthetic/plain-comment rule, not a Siemens alarm placeholder grammar. `unknown` token grammar blocks edits.

The [synthetic bilingual fixture](../../fixtures/translations/README.md) and independent expected values exercise the package contract without claiming Siemens layout fidelity. The [native feasibility packet](../../fixtures/translations/native-feasibility-request.json) is non-executable and requires a valid disposable native fixture, category/layout capture and current admission before later native qualification. The [API operation handoff](../../fixtures/translations/api-operations.json) records exact installed public members and the manual-only CPU language attributes for AC-01 reconciliation. The [captured read profiles](../../fixtures/translations/native-tia21-read-20261015/README.md) retain the original two-capture packet and four later captures from the frozen helper. Independent Python ZIP/XML decoding matches the seeded block comments exactly in `de-DE` and `en-GB`; the production reader separately verifies all twenty records across the four later workbooks. Common records retain identical opaque keys and text despite different row positions. Every `System Texts` sheet contains headers only. The native five-argument call with an empty object list was refused; the retained result does not interpret empty as all.

The last observation is retained as a category/object combination semantics gap. The frozen helper source confirms the single category argument; native call success does not mean its output was restricted to that category. Do not expose category intersection semantics until further native probes explain this behavior. The [category-filter investigation](translation-category-filtering-20261015.md) independently reproduces the leakage, adds a complete-row scope verifier with 14 checks, and checks the installed/online documentation gap. A later sequential 14-case native probe produces ten workbooks and four explicit null/empty refusals; independent and managed readers verify 28 rows and seven comparisons. Category leakage persists on both PLC software and DeviceItem selection. Empty selected-block exports provide no positive filtering control. Imports remain disabled. The earlier verification receipt (`artifacts/expansion-foundation-20261015/native/translation-verification-01.json`) remains unchanged.

Observed layout is Transitional SpreadsheetML with nine package parts per workbook and internal package-absolute relationship targets. Both visible sheets have headers `Category`, `ViewPath`, `Internal ID`, `Substitutions`, `de-DE*`, `en-GB`, followed by `ref="0"` through `ref="15"`. Exact keys occupy C, source E and target F. Data rows populate A:F only; D is empty in these captures. The category strings retain their observed angle-bracket wrappers. All cells use shared strings and style index 0. Styles contain Calibri 11 and three cell formats, including text/date formats that are not selected by these cells. No formulas, rich runs, comments or hidden sheets are present. `docProps/custom.xml` records `TIA_Version=1.3`; this is workbook metadata, not the installed Portal release number.

These capture-specific profiles remain `unqualified-explicit`, set `TokenGrammar=unknown`, and disable shared-string conversion, clear and missing-cell creation. The managed refusal probe confirms a changed candidate is blocked. Their provenance pins each original workbook hash and native export receipt; keys must not be transplanted into another project or capture. Native project bytes were locked, so the captured project content digest remains unknown. No import, placeholder/substitution semantics, native no-op roundtrip, compile, fresh reopen or recovery acceptance is claimed.

TR-F00's profile/fixture/API handoff remains present. TR-F01 now has this narrow genuine export/layout/filtering packet; remaining object/category/language/product semantics remain open. TR-I01 has a tested bounded envelope and preserving explicit-map writer, plus observed native read compatibility. Broader rich/strict/ZIP64 formats, native write semantics, scale acceptance and import/lifecycle packages remain required.
