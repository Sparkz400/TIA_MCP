# HMI / explorer integration hook

Classic ordinary screen inspection now uses the six public screen scopes and retains optional `screenRole` metadata (`regular`, `template`, `popup`, `slideIn`, `globalElements`, `overview`). `coverage.screenScopes` distinguishes complete, absent, unavailable and truncated scopes. Explorer nodes remain `hmiScreen`; their exact paths separate roles and folders. Additional Classic roles route details to screen metadata, while regular screens retain the existing item route. Added-role item parsing and ordinary source export remain unsupported/unqualified; these observations confer no mutation authority. See [offline verification](../verification/classic-screen-inventory-20261023.md).

The explorer owns `OpennessSession.ProjectModel.cs`, `ProjectModelStore`, and `ProjectModelProviders`. HMI owns its native extraction and adapter. Do not replace the explorer dispatcher or add a parallel project model store.

The shared JSON schema is `contracts/project-model.v1.schema.json`. Nodes use `name` (not `displayName`), `nodeId`, `parentId`, `kind`, `origin`, exact canonical `objectPath` for native nodes only, `access:{state}`, `detailAvailability`, `metadata`. HMI nodes have no invented `plcPath`. Canonical HMI paths are supplied by HMI identity v2; the explorer wraps them in its session/snapshot/project-copy bound v1 selection reference.

`OpennessSession.ProjectModel.cs` provides optional partial hooks implemented in an HMI-owned partial file:

```csharp
partial void RegisterProjectModelProviders(List<IProjectModelProvider> providers);
partial void RegisterTypedProjectModelProviders(List<IProjectModelProvider> providers);
partial void CaptureHmiProjectModel(Project project, string hmiPath, string parentId, ModelCapture capture);
partial void ReadHmiProjectModelRelationships(JObject snapshot, JObject reference, JObject node, JObject args, ref JObject result);
```

`RegisterProjectModelProviders` adds read-only HMI provider implementations. `IProjectModelProvider` has `ProviderId`, `Supports(JObject node,string facet)`, and `Inspect(ProjectModelProviderRequest request)`. The request contains immutable exact `Reference`, `Node`, `Facet`, `MaxItems` and `MaxBytes`. HMI details use facet `hmiDetails`; previews use `hmiPreview`. Return the versioned provider response validated by `ProjectModelProviders.Validate`. A provider must keep the exact reference and must not turn a metadata revision into a content hash.

Capture is called after the native HMI software node is added under its hardware item. Its `parentId` is that existing root node. `capture.Add(path,parentId,kind,name,plc:null,scope:hmiPath,metadata)` returns the inserted node ID or null at the bound. Use native group enumeration, or mark truly synthetic display ancestors with final `native:false`; do not declare path-derived groups native. The bounded context exposes `Budget`, `Remaining`, `MaxDepth`, `MaxBytes`, `Nodes`, `Warnings`, `ProviderCoverage`. Count native visited work against `Budget`, and remember Add itself consumes one visit. Stop immediately on `Budget.Truncated`/zero remaining. Contributions should add coverage records to `ProviderCoverage`; warnings are normalized to strings by the explorer. Do not put read timestamps, source content hashes or transient provider-session IDs in stable capture metadata, because metadata verification compares the capture's normalized nodes.

The relationship hook can supply a normalized bounded graph result; null leaves the unsupported fallback. Edges use kinds from the schema and captured endpoints `{nodeId,objectPath}`. Missing exact endpoints must be null with explicit `unresolved` evidence, never same-name substitutions. Every edge carries evidence origin/resolution, sourcePath/location, capturedAtUtc and a separate contentRevision. The hook runs only after exact snapshot reference validation and a native metadata verification. Preserve provider-specific uncertainty and controller/connection ownership. Capture-bound API graph ceilings are depth 5, 500 nodes, 1000 edges and 512 KiB returned graph payload.

Store `RememberDetails` / `RememberRelationships` persist separate observations for portable export without changing the metadata revision. Aggregate retained relationships are bounded to 1000; nodes including details to 64 KiB, snapshot to 32 MiB. Provider attachments are structured HMI/typed data, never executable project scripts or arbitrary HTML.
