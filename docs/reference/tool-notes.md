# Tool details moved out of descriptions

A tool description holds what a model needs to call the tool correctly. The prose below was removed from the longest descriptions: per-version history, bounds, edge cases and safety detail. It is unchanged and still describes the current behavior. This page is hand-written; the generated tool list is [tools.md](tools.md).

The 0.5.0 surface redesign shortened every description over about 600 characters to its essentials and moved the full
text here, and folded the per-family record tools into `review_list`, `review_reopen`, `review_page` and `review_artifact_read`,
whose per-kind behavior follows. Tool names in the moved text are the current ones; its parameter names (`recordId`, `uploadId`, `cursor`, `pageSize`, `maxItems`) are those before 0.5.0, which the [MCP surface](mcp-surface.md#migration-to-050)
lists the renames.

## change_prepare

Payload schema per kind: resource tia://change-payloads/{kind} (JSON Schema; the field index is tia://contracts/change-kinds.v1.json). Prepare an offline engineering change: kind and payload, exact project/PLC targets, preview, artifact hashes and conflict checks. Optional intent {decisions [{id, source, statement, target?, symbols?, meaning?}], observedFacts, assumptions} records confirmed machine intent in the hash-bound preview, separates it from facts and assumptions, and flags (intent.conflicts) or recognizes (intent.previouslyConfirmed) decisions of earlier applied changes in the same project; it is never evaluated, and machine safety behavior is not verified. Returns changeId/previewHash for change_apply and the project's unsaved state (isModified). Refuses with RecoveryRequired while another change on the same project in this TIA process is unresolved. First inspect change_status: a bounded Classic screen failure may already be verified rolled_back or not_applied and allow a new preparation without restarting TIA. For a lost response to a terminal Classic screen change, use engineering_admission_reconcile in the open project. An unverified recovery remains held for change_restore. Compile-only kinds: plc_compile takes payload:{} plus exact plcPath; hmi_compile takes payload:{target}; device_compile takes payload:{devicePath}; project_compile takes payload:{}. Completed compiler findings are reported separately from execution failures. Source/XML must explicitly describe intended objects. Kind tag_table_import_xml also takes rows instead of xml: {tagTableName, tags:[{name, dataType, logicalAddress, comment?}], commentCulture?} (1..2000 rows) adds or updates those tags in the named table, creating it if absent, and keeps its other members; its preview carries hardwareCrossCheck, an advisory comparison of the imported I/O addresses with configured module address ranges that never blocks the import. Kind tag_set also takes items instead of one tag: {items:[{tagTableName or tagTablePath, memberName, attributes:{Name?, DataTypeName?, LogicalAddress?}}]} (1..500 edits in one software scope) applies all of them under one fingerprint check, checkpoint archive, compile and save; preview.items lists every edit, any refused item (a safety tag, an F-I/O address, a name collision) refuses the whole change before a write, and every item is read back. A safety tag is refused by tag_set with one exception: a single tag_set {tagTableName or tagTablePath, memberName, attributes:{Name}, safetyAcknowledged:true} renames it (Name only, never inside items, safety offline program writable; the preview holds safetyBefore and a warning, and nothing validates or accepts the safety program). Kinds constant_set, tag_create, constant_create, tag_delete, constant_delete, tag_table_create, tag_table_rename, block_rename, block_attributes_set, type_rename, block_number_set, group_create, group_rename, block_delete, call_parameter_set, graphical_operand_set, graphical_network_patch and graphical_network_insert take {items:[<one payload of that kind>, ...], scopePath?} (1..100 items in one software scope) the same way: each item is prepared with that kind's own checks, preview.items lists them, two items may not edit the same object or produce the same name or block number, a group_rename item may not name a group inside another item's group, call and graphical items need distinct blocks (each replaces its whole block and is read back on its own), and a refused item refuses the whole change. Kind hmi_text_list_import takes {schemaVersion:1, target, expectedContentHash, recordId, outputId?}: the Host reopens that hmi_text_list_author/generate_set record and refuses content V21's import would change. Kind hmi_classic_screen_edit takes classic_xml_import of an existing regular Classic RT Advanced screen; it compares all regular screens of that HMI only, explicitly excluding shared resources and other HMIs. Kinds hmi_classic_import (Classic classic_xml_import of a screen or tag table, or screen BackColor scalar_property_set), hmi_external_tag_create (Unified external_tag_create), hmi_screen_create (Unified screen_create and item_create), hmi_dynamization_create (Unified dynamization_set) and hmi_event_handler_create (Unified event_handler_set) take the hmi_engineering payload of their operation. Large inputs by reference: source_upsert takes sourceRef, and block_import_xml, hmi_classic_import and hmi_classic_screen_edit take xmlRef, instead of inline source/xml, either a committed artifact_upload ref (upload:...) or a file under the Host artifact directory (at most 2 MiB UTF-8); the Host inlines the exact text, records payload.inputReference {reference, bytes, sha256} and the preview hash covers it like inline text. Returns a summary (state, changeId/previewHash, warnings, effects, payload strings over 1 KiB as length+SHA-256, artifact paths) unless includeDetails=true; change_status(includeDetails=true) returns the full view. Does not change the project; writes preview artifacts.

Full description before 0.5.0: Prepare an offline engineering change: kind and payload, exact project/PLC targets. Writes preview artifacts only; the project is not changed. Payload schema per kind: resource tia://change-payloads/{kind} (index: tia://contracts/change-kinds.v1.json). Returns changeId and previewHash for change_apply, the preview, warnings, effects and the project's unsaved state (isModified); a summary unless includeDetails=true (change_status includeDetails=true returns the full view). Optional intent {decisions [{id, source, statement, target?, symbols?, meaning?}], observedFacts, assumptions} is recorded in the hash-bound preview and never evaluated; it flags (intent.conflicts) or recognizes (intent.previouslyConfirmed) decisions of earlier applied changes; machine safety behavior is not verified. Refuses with RecoveryRequired while another change on the same project is unresolved: inspect change_status first. Compile-only kinds: plc_compile (payload {} and plcPath), hmi_compile {target}, device_compile {devicePath}, project_compile {}. Batch kinds (tag_set 1..500 edits; constant_set, tag_create, block_rename, group_create, block_delete, call_parameter_set and similar 1..100 items) take {items:[...], scopePath?} in one software scope: one fingerprint check, checkpoint, compile and save, every item read back, and a refused item (a safety tag, an F-I/O address, a name collision) refuses the whole change before any write. Large inputs by reference: source_upsert takes sourceRef; block_import_xml, hmi_classic_import and hmi_classic_screen_edit take xmlRef (upload:... or a file under the Host artifact directory, at most 2 MiB). Per-kind rules (safety tag rename, tag_table_import_xml rows and hardwareCrossCheck, HMI kinds, recovery after a lost response): docs/reference/tool-notes.md#change_prepare.

Not natively qualified on a protected project yet.

## runtime_capture_start

Saved source instance/declarations are re-resolved; unresolved or mismatched datatypes refuse. Retains explicit caller mappings, not verified online address equivalence or program identity. Reusing the same ID observes intent without source reread or restart. Optional handoffRef requires reviewId and a retained consistent runtime handoff matching the actual session owner/context/subject/mode/credential. SimulationRecordsActive / SimulationRecordsInactive otherwise; sim_release and the worker's shutdown disarm too. status is passed to the runtime unchanged; how a CPU reports it in STATUS is the runtime's.

## sim_state

Change only a PLCSIM instance this session created or adopted (otherwise OwnedInstanceRequired): powerOn, powerOff, run, stop, or memoryReset (restarts the virtual controller with its loaded program). Refused with SimulationCaptureModeActive while a cycle-synchronous capture holds the instance. timeoutMs (1000-60000, default 30000; twice it for powerOn, whose failure is followed by a powerOff) must end 5 s before the Host's --timeout-seconds, otherwise InvalidRequest. Exact local simulator identity is rechecked. Never targets a physical PLC. SimulationConfigurationPasswordRequired requests the separate confidential configuration-protection password; user login requires username and password only if separately requested. This tool accepts no raw credentials; follow the returned guidance and server authentication instructions.

## sim_test

Execute bounded simulation stimulus/capture/assertion steps and save a report. signals:[{symbol,type}]; steps:[{delayMs,writes:[{symbol,type,value}],assertions:[{symbol,type,operator,expected,tolerance}]}]. Operators eq/ne/gt/gte/lt/lte. Steps with writes and virtualTime:true need an instance this session created or adopted (otherwise OwnedInstanceRequired); a step write to a symbol whose tag-list area is the output area refuses the scenario with InvalidRequest before its first write. Wall-clock polling is not scan-accurate. virtualTime:true runs the scenario in TimespanSynchronized_C: every wait is a StartProcessing span of virtual time, samples are read while the CPU is frozen, elapsedMs is virtual time, and the previous operating mode is restored. Duration/sample bounds are enforced by the adapter; its 90 s execution cap needs a Host --timeout-seconds of at least 105, otherwise InvalidRequest.

## simulation_discovery_baseline

Read-only PN/IE / PLCSIM discovery for the worker-owned scratch PLC, before sim_create, while no PLCSIM Advanced instance is registered. Requires Softbus and does not change it. Records either nothing or exactly one all-zero Runtime Manager entry; the next simulation_provision_scratch_credential in this worker, same TIA session, project and PLC, may exclude only that single exact entry, at each of its discovery checks only while the baseline is under five minutes old and the same Runtime Manager process runs. A new baseline call first discards any earlier one. Never accepts any other device. Side effects: initializes the PLCSIM Advanced API, which may start the Runtime Manager and keeps it for the worker's lifetime, and stores that one baseline, which loosens the next provisioning isolation check as described.

## simulation_provision_recover

Recover from a held (outcomeUnknown) credential-provisioning attempt in one call: tia_detach (refused first with UnsavedProject while any open project has unsaved edits, since detaching discards them), tia_start, simulation_provision_reconcile for admissionId (evidence-checked; a held result stops here with its reasons) and project_open of the scratch project. Reports each step and stops at the first failure. Never powers, downloads, provisions, saves or replays; a fresh instance and a new provisioning attempt (with the user's TLS authorization again) stay separate calls, listed in status.nextSteps.

## simulation_provision_scratch_credential

Provision an existing generated scratch CPU configuration credential to its ticket-bound owned local PLCSIM instance. Requires a saved scratch project (project_save after simulation_download when it reports saveRequiredBeforeProvisioning), matching generated-card evidence, DPAPI credential metadata, isolated Softbus and an explicitly verified PLCSIM connection. Creates a full project recovery archive in owned storage before card staging or startup; does not automatically save unsaved edits. May start the virtual CPU for provisioning and returns it OFF. Optional trustOwnedEmptyCpuCertificate requires explicit user authorization for first-use TLS trust on this freshly created owned empty CPU; its certificate is pinned within the attempt. The authorization covers one attempt on one owned empty CPU, not a certificate hash: a recreated instance presents a different certificate, which the same flag trusts, so get the user's authorization again for each attempt (and name the new hash) when they approved a specific certificate. Default rejects TLS trust. Accepts no raw password, network adapter or target address; protection stays enabled. This does not prove RUN or program execution.

## software_inspect

Inspect PLC tag tables, tags/constants, PLC data types, software units and their blocks. Bounded offline results report missing or unsupported scope. Filters for large projects: groupPath (group names from the top, e.g. "Station 3000", matched below blocks, tags, types and technology; or a full group path from groups[]) and namePrefix (case-insensitive prefix of block, tag-table, type and technology-object names). With a filter only matching rows count against maxItems. Group paths (softwareScopes[].groups) never count against maxItems: they have their own bound of the same size, reported by groupsTruncated and groupTruncation, and namePrefix does not narrow them. include (comma-separated: blocks, tags, constants, types, technology) reads only those sections, so maxItems is not spent on the others, and leaves the group paths out; compact=true returns each tag as name, dataType, logicalAddress (and isSafety when true). Every tag table reports tagCount and constantCount with tagsTruncated/constantsTruncated, and truncation names the first place the item bound cut the result.

## technology_profile_review

Review committed technology-profile-review-request.v1/v2/v3/v4 JSON against an exact saved technology object: supplied profile identity, parameters, relationships and explicit unknowns. No native compatibility, write authority or motion. 4 MiB; 4096 parameters and 1024 relationships per phase; at most 500 changed parameter/relationship proposals (including encoder changes in v4). v2 retains independently uploaded source files: up to 16 files, 16 MiB each and 64 MiB total. v3 adds supplied consumers and bounded same-PLC saved context. v4 retains up to 256 encoder observations per phase: module, splitModules, channel, addresses, dbMember, startdriveTelegram or unknown routes, exact saved selectors, explicit bit/byte/unknown units and sensor-index contradictions. Telegram targets bind original retained drive record/phase/ID in the same saved review; at most eight drive records and 64 MiB of drive records/inputs. Channel/member existence, wiring and eligibility remain unverified.

## tia_attach

Attach to an explicitly selected running V21 process. Siemens may display its own Openness access dialog. Does not change the project or connect online. The result lists attachedSessions, the other Openness clients of that Portal. An attach has been reported to wait while another client is in the middle of a call (isActive). waitForIdleSeconds (0..60) checks first: if another client is still in a call after that many seconds, the attach is refused with OpennessClientBusy naming it (busyClients; processRunning:false marks a client whose process has exited) and nothing is attached. Without it the attach behaves as before. This tool never disconnects another client or ends its process.

## tia_detach

Release the worker's TIA connection. A user-owned TIA instance is only detached, never closed. For a worker-owned instance (tia_start), its projects are closed without saving (unsaved edits are discarded and listed in projectsClosed), the connection is disposed and the call waits up to waitForExitSeconds (0..300, default 30) for that Portal process to exit, reporting portalProcessId, processExited and processExitVerified. terminateOwnedIfRunning:true ends that exact owned process if it is still running after the wait; it can never reach another TIA process. PLCSIM instances stay registered: plcsimRegistrations lists them when this worker used the PLCSIM API (release them with sim_release before simulation_discovery_baseline).

## trace_analyze

Analyze a trace_read measurementId offline against original declarative hypothesis predictions. Conditions are {signalId,op:eq|ne|lt|le|gt|ge,value}, ANDed within when/expect. Reports supported/contradicted sample predictions or unresolved, bounded transition intervals, gaps and uncertainty. No script evaluation, causal proof or claim that an unreproduced fault is fixed. Persists an exportable report with original clock, program label, mode and time unit; supplied identities and clock synchronization remain unverified. v2 counts usable observations but all behavioral verdicts remain unresolved; bad/uncertain/missing/error values never enter statistics, and changes cannot bridge gaps, resets, epochs or missing timing.

## trace_compare

Compare two imported measurements without resampling. options requires reason, beforeAnchorSeconds, afterAnchorSeconds, windowStartSeconds, windowEndSeconds; anchors are explicit caller-selected events. Different source reviews or declared program identities require allowChangedSource:true; changed storage/instances require explicit signalMap:[{before,after}]. Types/units must match. Unknown options and malformed mappings refuse; time conversion and anchor subtraction must be exact. Retains both declared program identities, clock labels, modes and original time units beside raw-sample statistics and transition intervals. Caller-selected anchors do not synchronize clocks; never proves a fix or causality. v2 requires beforeClockId, beforeEpoch, afterClockId and afterEpoch; it selects each original clock/epoch separately. Mixed v1/v2 inputs refuse. v2 includes complete-epoch quality and original per-reading times without resampling.

## trace_read

Import exactly one host-owned hashed artifact {path,sha256} or committed uploadRef against exact tracePlanId (uploaded bytes are retained independently): trace-measurement.v1 or trace-measurement.v2 JSON, or v1 UTF-8 CSV with explicit csvOptions (delimiter,decimalSeparator,headerRecord,timeColumn,timeUnit,columns:[{signalId,column,unit}],mode,clock,programIdentity,quality; optional missingValues/settingsReadbackEvidence). Supports <=10000 samples; preserves negative pre-trigger times and units. Rejects decimal precision loss. No native Siemens binary decoder or automatic CSV dialect qualification. Native originals/readback evidence retained; polling cannot claim atomic/scan-synchronized quality. v2 retains explicit clock domains/epochs, per-reading status/error/timestamps, absent readings, irregular/reset times and capture completeness. v2 JSON is retained byte-exactly; no v2 CSV coercion. See docs/reference/diagnostic-measurement-quality.md. Offline only.

## vci_fetch

Fetch branchName from the one Host-configured remote into a new fetched-revision record. With parentRevisionRef (a committed or fetched revision checked out on the same branch name) the copied repository fast-forwards to the remote commit and refuses divergent remote history; without it a new repository takes the remote commit. Optional expectedRemoteCommit pins the reviewed remote commit. A local remote must pass the same minimal bare-repository check as vci_push. The remote tree must hold only regular files without .gitattributes/.gitmodules; working files read back as the exact remote blobs. The record serves as parentRevisionRef, history, branches, materialize, file read and package capture source. Prior records never change; no native engineering.

## vci_prepare

Prepare an offline local Git revision from 1..1000 explicitly selected files and committed uploads, at most 16 MiB/file and 64 MiB raw tree. Null uploadRef with delete=false creates an empty file; delete=true removes an exact parent file. Optional parentRevisionRef must be a Host-issued committed or fetched revision. Each candidate owns a separate repository. Optional branchName names the initial branch or creates/selects a new unused branch at the exact parent commit; omission inherits the parent branch (main for a new repository). Existing different branches are never reset or switched into. Retains raw bytes, tracked Git diff and file manifest; new files are reviewed through file reads. Returns planSha256 for explicit commit review. No native export/import or user repository paths; remote delivery uses vci_push and vci_fetch.

## vci_push

Push the exact commit of a Host-issued committed or fetched revision to branchName on the one Host-configured remote (--git-remote; a local bare repository unless --git-allow-network-remote allows credential-free https). Compare-and-swap: the remote branch must equal expectedRemoteCommit (omit when it must not exist yet) and the commit must descend from it; there is no forced update. Reads the remote branch back. Refuses a local remote that is not a minimal bare repository (the core-only config allowlist, no hooks, alternates or other indirection), checked again right before dispatch. A dispatched push without its receipt stays outcomeUnknown; inspect the remote before repeating. No credentials, caller URLs or native engineering.

## watch_table_monitor

Monitor the rows of an offline V21 watch table (or, with forceTable=true, a force table) on a PLCSIM Advanced instance this Host owns: instanceId, instanceName and the creationId it was created or adopted with. Reads the table as watch_table_read does, resolves rows [offset, offset+count) (count 1..64) by symbol against the instance's own tag list, then reads the resolved symbols samples times (1..20, intervalMs 100..5000 apart) over the PLCSIM API. Absolute-address rows (%I, %Q, %M as bit, byte, word or double word) are read from the process image with sim_area_read and reported as raw bytes plus an unsigned big-endian value; peripheral (:P), data block and other addresses are unresolved. Comment rows, symbols missing from or ambiguous in the tag list and types without a typed PLCSIM read (Struct, Char, WChar, ...) are reported per row and not read. Read only: the values of one sample come from sequential reads, not one scan; ModifyValue, ForceValue and ForceIntention are stored configuration and are never applied. Nothing is modified or forced (no public V21, PLCSIM, Web API or OPC UA route forces a value). The instance's program is not compared with the project. Never a physical PLC.

## xref_query

## plc_physical_download

Download the selected PLC's software (softwareScope changes, the default, or all; hardware:true adds the hardware configuration) to a REAL PLC. This can stop the PLC and move the machine it controls: confirm the machine is in a safe state first. Required: acknowledgeLiveTarget:true, expectedPlcName equal to the selected PLC's name, the explicit route (pcInterface, targetInterface, expectedAddress as in plc_physical_online_compare) and a saved project. TIA's questions are answered only from acknowledgements: a stop needs acknowledgeStop, a data block reinitialization needs acknowledgeReinitialize and acknowledgeStop (otherwise actual values are kept where TIA allows it), startAfterDownload starts the CPU afterwards; any other question, a configuration password or a login stops the download. The operating state afterwards is not observed. Not qualified on a physical PLC yet; check every result in the TIA Portal.

## plc_physical_online_compare

Go online to a real PLC, run PlcSoftware.CompareToOnline and go offline again. Writes nothing to the PLC. The route is explicit: pcInterface (and pcInterfaceNumber, default 1) and targetInterface from plc_physical_targets, mode (default PN/IE), and expectedAddress, which must be an address the project configures for this CPU. PLCSIM interfaces are refused. Login and password challenges are never answered (PhysicalAuthenticationRequired); a TLS certificate is trusted only when its SHA-256 equals trustedCertificateSha256, which you check out of band. Not qualified on a physical PLC yet; check every result in the TIA Portal.
