# Tool details moved out of descriptions

A tool description holds what a model needs to call the tool correctly. The prose below was removed from the longest descriptions: per-version history, bounds, edge cases and safety detail. It is unchanged and still describes the current behavior. This page is hand-written; the generated tool list is [tools.md](tools.md).


## change_prepare

Payload schema per kind: resource tia://change-payloads/{kind} (JSON Schema; the field index is tia://contracts/change-kinds.v1.json). Prepare an offline engineering change: kind and payload, exact project/PLC targets, preview, artifact hashes and conflict checks. Optional intent {decisions [{id, source, statement, target?, symbols?, meaning?}], observedFacts, assumptions} records confirmed machine intent in the hash-bound preview, separates it from facts and assumptions, and flags (intent.conflicts) or recognizes (intent.previouslyConfirmed) decisions of earlier applied changes in the same project; it is never evaluated, and machine safety behavior is not verified. Returns changeId/previewHash for change_apply and the project's unsaved state (isModified). Refuses with RecoveryRequired while another change on the same project in this TIA process is unresolved. First inspect change_status: a bounded Classic screen failure may already be verified rolled_back or not_applied and allow a new preparation without restarting TIA. For a lost response to a terminal Classic screen change, use engineering_admission_reconcile in the open project. An unverified recovery remains held for change_restore. Compile-only kinds: plc_compile takes payload:{} plus exact plcPath; hmi_compile takes payload:{target}; device_compile takes payload:{devicePath}; project_compile takes payload:{}. Completed compiler findings are reported separately from execution failures. Source/XML must explicitly describe intended objects. Kind tag_table_import_xml also takes rows instead of xml: {tagTableName, tags:[{name, dataType, logicalAddress, comment?}], commentCulture?} (1..2000 rows) adds or updates those tags in the named table, creating it if absent, and keeps its other members; its preview carries hardwareCrossCheck, an advisory comparison of the imported I/O addresses with configured module address ranges that never blocks the import. Kind tag_set also takes items instead of one tag: {items:[{tagTableName or tagTablePath, memberName, attributes:{Name?, DataTypeName?, LogicalAddress?}}]} (1..500 edits in one software scope) applies all of them under one fingerprint check, checkpoint archive, compile and save; preview.items lists every edit, any refused item (a safety tag, an F-I/O address, a name collision) refuses the whole change before a write, and every item is read back. A safety tag is refused by tag_set with one exception: a single tag_set {tagTableName or tagTablePath, memberName, attributes:{Name}, safetyAcknowledged:true} renames it (Name only, never inside items, safety offline program writable; the preview holds safetyBefore and a warning, and nothing validates or accepts the safety program). Kinds constant_set, tag_create, constant_create, tag_delete, constant_delete, tag_table_create, tag_table_rename, block_rename, block_attributes_set, type_rename, block_number_set, group_create, group_rename, block_delete, call_parameter_set, graphical_operand_set, graphical_network_patch and graphical_network_insert take {items:[<one payload of that kind>, ...], scopePath?} (1..100 items in one software scope) the same way: each item is prepared with that kind's own checks, preview.items lists them, two items may not edit the same object or produce the same name or block number, a group_rename item may not name a group inside another item's group, call and graphical items need distinct blocks (each replaces its whole block and is read back on its own), and a refused item refuses the whole change. Kind hmi_text_list_import takes {schemaVersion:1, target, expectedContentHash, recordId, outputId?}: the Host reopens that hmi_text_list_author/generate_set record and refuses content V21's import would change. Kind hmi_classic_screen_edit takes classic_xml_import of an existing regular Classic RT Advanced screen; it compares all regular screens of that HMI only, explicitly excluding shared resources and other HMIs. Kinds hmi_classic_import (Classic classic_xml_import of a screen or tag table, or screen BackColor scalar_property_set), hmi_external_tag_create (Unified external_tag_create), hmi_screen_create (Unified screen_create and item_create), hmi_dynamization_create (Unified dynamization_set) and hmi_event_handler_create (Unified event_handler_set) take the hmi_engineering payload of their operation. Large inputs by reference: source_upsert takes sourceRef, and block_import_xml, hmi_classic_import and hmi_classic_screen_edit take xmlRef, instead of inline source/xml, either a committed artifact_upload ref (upload:...) or a file under the Host artifact directory (at most 2 MiB UTF-8); the Host inlines the exact text, records payload.inputReference {reference, bytes, sha256} and the preview hash covers it like inline text. Returns a summary (state, changeId/previewHash, warnings, effects, payload strings over 1 KiB as length+SHA-256, artifact paths) unless includeDetails=true; change_status(includeDetails=true) returns the full view. Does not change the project; writes preview artifacts.


## hmi_component_review

Review a committed hmi-component-review-request.v1/v2/v3/v4/v5/v6/v7 upload against exact saved PLC component and HMI destination reviews. Compare explicit component/interface mappings, proposed HMI outputs and independent baseline/current/proposed files; report type changes, collisions, ownership and drift. v2 requires impactLimits and adds separate bounded incoming consumer paths for each saved component/destination snapshot; no cross-snapshot joins, invented bindings or complete-coverage claim. Retain originals across upload release/restart. v3 adds independent post-operation observations, compared by exact file bytes with the reviewed create/update/remove/retain intent. Missing, changed and unexpected files are reported; declared completeness never proves native effects. v4 adds explicit classic-screen-backcolor.v1 expectations derived from current files with exact owner/value checks; proposed and observed documents are independently checked, including all other XML content and the declaration. Unassessed files remain visible. v5 adds explicit v21-full-fb-library-version.v1 associations between retained original exports and exact saved FB paths. Report type/version GUID agreement, contradictions, unavailable observations and unassociated selected components. Empty expectations allow association-only review. Expected effects and associations share the 64 MiB examined-XML budget. Identifier agreement grants no native identity, content, dependency or runtime qualification. v6 adds exact direct dependency indices and target paths within each selected saved scope, with optional original-export associations. Report missing mappings, duplicate references, conflicting type identities and cycles; no name joins or complete native closure. Bounds: 1000 entries per dependency observation, 20000 total references and 4096 explicit dependency mappings. v7 connects explicit dependency selections to exact same-scope saved consumers, supplied member bindings and existing output-effect checks. Original disagreement and incomplete evidence remain visible; a 1 MiB prefix limit records omitted association indices. No complete mapping or native impact is inferred. No scripts, native generation/writes or qualification bypass. Bounds: 4 MiB request, 256 outputs, 1024 mappings, 32 files at 16 MiB each/64 MiB total; per-snapshot traversal depth 1..5, paths 1..200, edge visits 1..20000, path bytes 1 MiB.


## hmi_text_list_author

Author downloadable plain Unified text-list configuration and TextLibrary YAML candidates from a committed unified-text-list-author-request.v1/v2/v3 uploadRef, or reopen/revalidate a retained authoring recordId; supply exactly one. v2 profile unified-bool-binding-text-list.v1 derives one Bool list from an exact revalidated v7 Unified hmiResource output and component binding, with explicit languages and False/True translations. v3 profile unified-integer-state-text-list.v1 supports exact captured SInt/USInt/Int/UInt/DInt/UDInt/LInt types with 1..256 explicit disjoint SingleValue/Range states and translations. Missing value coverage and original selected dependency associations stay explicit; requireFullTypeCoverage blocks candidates with gaps. State additions/removals/relabels are supported; output/list/library/file renames and implicit type conversion are refused. Regeneration requires a previous author record and matching independent baseline/current candidate pairs; relevant conflicts suppress both candidates. Explicit retainOutputIds preserve selected peer bytes. Reopen checks original reviews, previous candidates and output bytes; predecessor depth 16 and lineage input budget 128 MiB. Explicit languages/default, text translations, list entries and references are required. Supports Decimal SingleValue/Range/From/To and nonnegative SingleValue BitNumber/Bool (Bool 0 or 1); overlaps, duplicate names, missing/unused translations and ambiguous references refuse. Signed 64-bit integer encoding is not native numeric-range certification. Bounds: 4 MiB request, 128 lists, 4096 total entries/texts, 32 languages, 16384 UTF-16 units per translation, conservative 8 MiB/file and shared 512 MiB retention. Original intent and both candidates survive upload release/restart; reopen recomputes files and refuses changed records. Download with artifact_read, then supply candidates to independent component review. No native import, existing-file rewriting, formatted/system text-list editing, project language activation, ownership/consumer/preservation or native qualification claim.


## hmi_text_list_generate_set

Generate or reopen retained offline Unified text-list sets from a revalidated v7 review; exactly one committed request uploadRef or retained recordId. v1 retains fixed-identity coordinated Bool/integer child authors. v2 requires an exact previous v1/v2 set and explicit add/update/rename output rows, previousOutputId, listName, bindingAction preserve/rebind, removeOutputIds and unchanged retainOutputIds. Every predecessor and current declared output/binding is accounted for. Complete baseline/current pairs must equal exact predecessor bytes; optional supplied proposed pairs must match derived candidates. Same-type rebinding requires exact before lineage and captured after declarations. Explicit unified-text-list-set-request.v3 permits integer-value-preserving.v1 typeConversion with fromType/toType for fixed-identity numeric updates among SInt/USInt/Int/UInt/DInt/UDInt. Original state intervals, translations and current files must remain exact and every listed value must fit both captured types. Overflow and unrelated conflicts refuse; this generates offline text-list candidates and never converts PLC values. V3 predecessors require explicit v3 evolution; no implicit conversion. Renames, swaps and removals are destructive-effect previews only, never file/native operations. Any conflict suppresses all published candidates. v2 retains its own output/transition lineage, preserving v1 and original author records. Reopen revalidates all original sources, predecessor sets/authors, candidates and selected peer bytes. 0..16 surviving v2 outputs, 32 candidate/peer files, 64 MiB bytes, 4 MiB input, 16 MiB record, depth 16, 128 MiB lineage input and shared 512 MiB retention. Final immutable record is completion; interruption may leave orphan immutable artifacts. Download references with artifact_read. No native/TIA/runtime access, ownership, complete project/dependency coverage or preservation qualification.


## hmi_inspect

Inspect bounded native HMI sections (request schema: resource tia://contracts/hmi-inspection.v1.schema.json): devices, connections, tags, screens, items, alarms, scripts or resources, or opt-in section=model for Unified typed whole-HMI attribute readback (optional modelRoots; script code hashed, secrets excluded). Select exact hmiPath/family and objectPath returned by discovery; repeated names are not identities. Classic screens include regular, template, popup, slide-in, global and overview roles with per-scope coverage; additional roles expose metadata without qualified item parsing. Per-section coverage distinguishes unavailable and unsupported data. Script inspection never executes project code. For a smaller model pass excludeSystem:true (no system tags, system text lists or OPC UA alarm types), modelRoots (for example Screens, TagTables, AlarmClasses) and rowMode=compact (rows with path and contentSha256 only, without identity or attributes; sectionContentSha256 compares a whole section in one value). Paging: rows come in pages of limit (default 100, at most 1000) and maxBytes (default 262144); page, at the top of the result, says which bound ended the page (stoppedBy). A target with an explicit kind must belong to the section (a device identity fits any section). Keep requesting nextOffset with the same expectedMetadataRevision until it is null. coverage.complete is true only on the last page of a complete capture (captureComplete alone ignores paging); totalItems, hasMore and pageCount give the size. Request schema: contracts/hmi-inspection.v1.schema.json.


## diagnostic_plan

Plan offline diagnosis from saved reviewId and report. Optional searchTerms/hypotheses, blockPath, instance:{dbPath,memberPath}, signals:[{id,role,reason,hypothesisIds,storagePath,memberPath}], context/observations, autoSignals:{seeds:[{scope:LocalVariable|GlobalVariable,components,reason}],maxSignals,maxDepth}. Optional testSuiteFinding:{relativePath,sha256,index} verifies a retained Test Suite receipt and explicitly selects its exact captured block; unresolved or cross-review findings refuse. Original finding/counters and unverified source provenance are retained. Optional alarmContext:{reviewId,nodeId,objectPath} retains an exact supplied alarm/supervision/hmiAlarm, captured ancestry and bounded direct evidence; it never selects executable storage. Optional alarmBindings:[{id,signalId,operand:{nodeId,objectPath},edgeIndices}] checks selected member nodes with metadata.alarmOperand profile alarm-operand.v1 against executable declarations and captured call arguments. Retains original directed paths and unresolved/type/owner gaps; this supplied profile is not a Siemens format or runtime alarm proof. Instance selection remains explicit. Ranks other candidates without choosing equipment. Exact qualified types, native root edges and bounded explicit SCL/FlgNet calls resolve captured instances. Automatic signal selection follows conservative dependencies and simple actual bindings; unsupported source/aliases remain gaps. Online addresses/observability remain unverified. Persists immutable case without native access. See docs/guides/trace-diagnostics.md.


## project_snapshot_capture

Save a persistent offline review: native hierarchy plus up to maxBlocks (0..200, default 25) exact standard block XML exports. Reports its stage (hierarchy, block n of N, verification) in progress notifications when the client sends a progressToken, and returns remoteAccess with the review's tia:// resource URI. request accepts projectName, plcPath, maxVisited, maxBlocks, blockPaths, maxRelationshipRoots (0..25, default 5), requireAllContent (refuse instead of saving when any block content is missing), hashProjectFolder (also hash every byte of the saved project folder; slower on large projects). capture.projectFolder reports the saved folder's file count, bytes and a path/size/time hash: the .ap21 file alone does not change on save. Check degraded and degradedReasons: they name failed exports, protected or unsupported blocks and blocks omitted by maxBlocks. A capture whose every export is refused for a read-only project is refused (ReadOnlyProject) instead of saved; pass fromTemporaryCopy:true to archive the open project, close it and capture a read-write copy instead (the original stays unchanged and the copy stays open). blockOffset pages through blocks beyond maxBlocks; capture.content.nextBlockOffset gives the next page. Captures bounded direct relationships for the first selected blocks. Native metadata is rechecked after exports; sequential content is not atomic. Protected/safety/unavailable content and omitted blocks stay explicit. Returns a content-hash reviewId usable after host restart. No project changes.


## project_open

Open an exact existing .ap21 project on the TIA host in an empty worker-owned instance: call tia_start first (NotAttached otherwise) and project_close a previously opened project (ProjectIsolationRequired otherwise). When TIA refuses the open and another TIA Portal has the project open, the error is ProjectLocked, naming that Portal's processId (lockOwners) beside TIA's own message; open it readOnly, use project_open_copy, or close it there. Does not upgrade, save or download it. Use a copied/test project for validation edits. readOnly=true opens it as a secondary (read-only) project: inventory and inspection reads work, TIA refuses exports (block/type/tag-table reads and other export-based tools) and every mutation is refused, both with ReadOnlyProject. A UMAC-protected project opens with umacUserName, umacUserType (project or global user) and umacCredential: a protected-credential-reference.v1 from the Host credential store (--credential-store create), bound to the exact full project path, user name and type (docs/reference/protected-credentials.md#project-open-umac-route). The Host seals the stored password for this one open; TIA's login request is answered once and never retried, so a wrong password fails with UmacLoginFailed or UmacLoginRejected instead of repeating. A reference bound to another path or user is refused (CredentialContextMismatch, with expectedBinding) before any secret is read. This tool accepts no raw passwords. Not natively qualified on a protected project yet.


## plc_station_upload

Upload the station from a ticket-bound owned PLCSIM Advanced instance into a new worker-owned project, in an empty TIA instance started with tia_start, through StationUploadProvider.StationUpload on PN/IE / PLCSIM (1) at the instance's single verified endpoint (same owned-instance guards as plc_online_compare). Missing products are not uploaded; passwords and other acknowledgements are rejected, and TLS trust too by default. Optional trustOwnedSimulationCertificate requires explicit user authorization for first-use TLS trust of this owned instance: after the owned target is revalidated, its first certificate is pinned within the upload attempt and every later challenge must present the same one; a challenge that offers no certificate and that TIA reports NonVerified (as V21's do) is accepted for this owned instance only and reported as unauthenticated TLS (tlsUnauthenticated), after which a challenge offering a certificate is refused. With runtimeCredentialMetadataPath, the generated runtime-user credential metadata of the scratch CPU that simulation_download loaded onto this instance, the one project-user login challenge is answered; any other credential is refused. Keeps every upload message, saves the new project even when partial, and returns its path. Never opens or changes an existing project and never powers or writes the instance.


## block_read

Export an offline block as original Siemens XML and inspect its metadata. Use qualified paths from project_inventory when names are ambiguous. Optional format: simaticSd exports native SIMATIC SD documents; generatedSource generates its SCL/STL/DB external source file without dependencies and needs a writable offline project, because any external source the generation leaves is deleted. Writes uniquely named, SHA-256 hashed local artifacts only; no project changes. render=text adds each network as readable text (networks[].text): LAD/FBD contacts and boxes as Boolean expressions, coils, instructions and calls with pin bindings, SCL networks as their source text; a network over 16384 characters is cut in the response and complete in textArtifact, a UTF-8 file written next to the XML that holds the whole block in one piece. A block without networks (a DB) is rendered as its declared interface instead (interface.text: sections, members, data types, start values, comments). A failed rendering, or a block with neither networks nor interface members, reports textUnavailable and keeps the export; no empty text file is written. Optional culture picks title/comment language. Inline xml is returned up to 64 KiB and never with render=text, unless includeXml=true (up to 512 KiB); the artifact always holds the full export.

## runtime_capture_start

Start bounded read-only Web polling for explicit host-owned selections. Supply caller-retained 32-hex captureId and request with attemptId, selectionIds, intervalMilliseconds (100..60000), durationSeconds (1..3600), optional maximumSamples (1..100000), maximumBytes (1..64 MiB), reviewId, representation (simple or raw). Optional association:{caseId,mappings:[{selectionId,signalId,reason}],assertedProgramIdentity} requires reviewId and maps every selection in request order to a unique diagnostic-case signal. Saved source instance/declarations are re-resolved; unresolved or mismatched datatypes refuse. Retains explicit caller mappings, not verified online address equivalence or program identity. Reusing the same ID observes intent without source reread or restart. Optional handoffRef requires reviewId and a retained consistent runtime handoff matching the actual session owner/context/subject/mode/credential. Bound original evidence is revalidated before every read; changes stop polling. This is evidence association only, never target/program/permission proof or operation admission. Optional source:'plcsim' with simulator:{instanceId,instanceName,signals:[{symbol,type,datatype}],cycleSynchronous,syncMode?, spanMilliseconds?} instead polls an exact PLCSIM Advanced instance this Host owns through the simulator worker: attemptId is its sim_create/sim_select creationId, selectionIds name the signals in order, datatype is the declared PLC type matching the typed read, representation simple, no handoffRef. cycleSynchronous puts the owned running instance into syncMode (SingleStep_C by default, or SingleStep_P/CP/CT/CPT, or TimespanSynchronized_C/P/CP with spanMilliseconds 1..60000 of CPU time per sample), steps one sync point per sample and restores the previous operating mode on stop, failure or Host shutdown; unowned instances are refused. At most one capture per session or instance and four workers. syncMode requires cycleSynchronous; CT/CPT use the existing overwritten minimum cycle time. A sync point need not be a full scan. Natively C, CP, CT and CPT completed; P stalled after one sync point on a CPU without a process image partition, and the previous operating mode was restored each time. No writes or reconnect/login; Web polling is not scan synchronized.
