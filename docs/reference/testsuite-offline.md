# Test Suite offline definitions, run plans and results

The pure implementation lives in [Core/TestSuite](../../src/TiaMcp.Core/TestSuite/) with [independent tests](../../tests/TiaMcp.TestSuite.Tests/). It implements TS-02 model/result/scope/scale slices and TS-03's shared durable operation binding. The [production Host integration](testsuite-production-jobs.md) adds ten registered style workflow tools, persistent queues/stops, a testable orchestration adapter and a compile-checked optional V21 single-rule boundary. Production native profiles remain disabled; this delivery has no automatic native worker loop or executed Siemens test. The [supplied-result review](testsuite-result-review.md) adds two offline Host tools with immutable original/report/JUnit artifacts and conservative saved-review associations. Current checks are recorded in its [verification](../verification/testsuite-result-review-20261016.md); earlier 580-, 354- and 233-check runs remain historical evidence. See the [identity-text verification](../verification/testsuite-identity-text-20261016.md) for the preceding aggregate and [finding-counter verification](../verification/testsuite-findings-20261016.md) for the current source and targeted results.

`TestSuiteDefinitionCapture` preserves original bytes privately and returns copies. It binds an explicit family/profile, exact [captured identity](engineering-capture-identities.md), scope, dependency IDs and unresolved syntax. Dependency IDs, unresolved-syntax entries, definition identities, execution profiles, job keys and session epochs refuse malformed Unicode and control characters before serialization or hashing. Valid Unicode remains exact: composed/decomposed forms and literal replacement characters stay distinct. Style XML receives bounded well-formedness checks with DTD/entities disabled. Application, system and set definitions remain opaque captured documents; no `.tat`, `.tst` or `.TTST` grammar is invented. Profiles must report incomplete scope/effects or unresolved syntax honestly, and those states block a runnable-coverage claim. Native-compatible parser profiles and roundtrip editing remain TS-00/TS-04 work.

`TestSuiteRunPlanner` validates bounded selection and dependency closure, detects missing/cyclic dependencies and mixed runtime resources, keeps explicit exclusions in required coverage, and keeps dependency-bearing sets intact. Selecting a set and its member or overlapping sets blocks duplicate dispatch, including transitive members. Serialized plans are rebuilt through the same validation; recomputing a hash cannot bypass these rules. Plans always set `nativeExecutionAuthorized:false`. Native availability, product/license, authenticated endpoint identity, protection, project checkpoint and resource leases remain separately required.

`TestSuiteResultNormalizer` retains the complete supplied native result tree as immutable JSON plus hash: native states, hierarchy, counts, paths, text and timestamp provenance remain intact. Parent/child counts are not summed into invented assertion totals. Unknown timezone stays unknown. Effective scope and collection completeness must be independently observed. Missing results, exclusions, warnings, information and unknown states cannot silently pass required coverage. Assertions are classified only when an explicit observed failure profile supplies that distinction; otherwise native errors remain execution errors.

JUnit export re-derives outcomes from the exact plan and retained raw captures, rejecting forged outcome labels or coverage gates. It represents each captured definition result as an execution unit, not a fabricated count of Siemens assertions. Its properties retain the failing required-coverage gate even when blocked/not-run units appear as skipped for CI display. Exact source, PLC, scope and object joins support style findings; missing or ambiguous native paths remain unresolved. A positive native error or warning counter produces a finding even when its state says `Success`. Findings preserve that state and the individual counters without summing parent/child totals. Clean zero-count success messages stay omitted. The supplied-result review now calls this projection; automatic project-health/diagnostic orchestration remains open. Message trees are bounded to 32 levels and 32 MiB of text; the complete report is bounded to 100,000 messages and 64 MiB of raw JSON. Unpaired Unicode surrogates are refused instead of being silently replaced during JSON encoding. Unknown fields in purported raw captures cannot disappear through a validated report roundtrip. No result normalizer operation executes native code or grants 1.0 acceptance.

`TestSuiteScopeCoverage` separately compares requested, effective and explicitly ignored objects for every required definition. Missing observations, incomplete reads, unexpected objects, exclusions and same-path objects on another PLC remain explicit gaps. Known content identities must match. `Validate` independently recomputes each status/gap and `Assess` combines the validated results and scope reports with canonical hashes. A capture's `ScopeVerified:true` cannot promote a run with observed scope gaps. These are supplied observations; genuine native scope/probe evidence remains separately required.

`TestSuiteJobState` is a **pure transition model**, not a persisted worker or resource broker. A stop before dispatch prevents the next dispatch; cleanup still needs observation. An in-flight stop leaves the native call running/unknown and never claims cancellation. Lost responses hold resources until explicit terminal reconciliation and independently verified cleanup. [TestSuiteStyleOperation and the TS-03 integration contract](testsuite-durable-jobs.md) now bind style plans to the shared AC-03 store with canonical project ownership, checkpoint/dispatch intent, required probes and seven verification gates. Tested authored fixtures cover persisted reopen, duplicate keys, conflicts, unknown-outcome retention, replay refusal and reconciliation. Native worker/executor integration remains open.

Timings are observations from the current host, not a performance SLA or native scale qualification. That historical suite reported 128 checks, including 21 shared-store integration checks; those test-unit definitions are not a coverage percentage.
