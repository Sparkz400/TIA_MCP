# Shared captured engineering identities

This is the minimum **AC-02 identity contract** used by the offline watch-table, VCI, translation and Test Suite modules. It does not close AC-02 native identity/probe qualification.

`CapturedObjectIdentity` retains the existing exact `projectPath`, `plcPath`, `scopePath`, `objectPath` and kind vocabulary. Selectors are opaque, bounded and case-sensitive; no trimming, Unicode normalization or invented vendor GUID occurs. Null PLC/scope means not supplied, not an implicit default scope. An unrecognized kind does not establish a native resolver for that kind.

`EngineeringSnapshotIdentity` binds an observation ID to a lowercase SHA-256 digest of the captured source manifest and an explicit TIA version. An observation ID is a bridge receipt identity, not a persistent Siemens revision. `EngineeringObjectReference` combines these and an optional content digest. The producer must hash the actual retained bytes/manifest; string validation alone does not verify that provenance.

The [Core guards](../../src/TiaMcp.Core/Engineering/EngineeringIdentity.cs) check exact object equality, same-project capture consistency, and expected-versus-observed content identity. `EnsureSameSnapshot` permits different objects in one project capture. `EnsureFresh` additionally requires the same object and identical content state, including known versus unknown content. This only establishes consistency between supplied captures. A later native apply must reacquire and validate the actual project/object/program state through the coordinator's admitted worker.

Use [the reference schema](../../contracts/engineering-object-reference.v1.schema.json) with `BridgeProtocol.Json` camel-case serialization. `CanonicalJson` is the RFC 8785 JSON Canonicalization Scheme, byte-identical to the Openness worker's: object keys sorted by UTF-16 code units, array order and nulls kept, ECMAScript number text (`1e3` is `1000`, `1E-7` is `1e-7`, `-0` is `0`, `1e+21` from 10^21 up), strings that escape only `"`, `\` and U+0000–U+001F (`\b \t \n \f \r`, otherwise lowercase `\u00xx`) and keep everything else, emoji included, as literal UTF-8, and no whitespace. A lone surrogate or a number outside the double range is refused with `InvalidRequest`, nesting deeper than 128 with `TraversalLimit`. One deliberate deviation: an integer literal beyond ±(2^53−1) keeps its exact digits, where RFC 8785 would round it through a double and two different integers could share a hash. Other numbers hash by value, so `1`, `1.0` and `1e0` are equal; both runtimes read a number literal with the same exact decimal-to-double conversion, because .NET Framework's `double.Parse` misrounds some (for example `2.2250738585072012e-308`), and the worker reads request floats from their text. Review diffs (`CanonicalJson.ExactlyEqual`) still report a change from `1` to `1.0`. [Shared vectors](../../fixtures/canonical-json/vectors.v1.json) pin both runtimes (`TiaMcp.Engineering.Tests` for the Host, `TiaMcp.ComponentQualification.Boundary.Tests` for the worker). Output consumers must preserve these semantics when recomputing hashes. Observation timestamps belong outside a semantic digest unless time itself is part of the evidence being bound.

## Hashes stored before RFC 8785

Builds before 1 November 2026 hashed in another form: the Host with ordinal key order through System.Text.Json's default encoder (non-ASCII text and ``+ < > & ' ` `` escaped as `\uXXXX`, number text as written), the worker with compact Newtonsoft JSON. A Host hash differs from its RFC 8785 hash when the content has non-ASCII text, one of those characters (every `+00:00` timestamp has one), a control character without a short escape, or a number with a fraction or exponent; a worker hash only for a number with a fraction or exponent, or U+0085, U+2028 or U+2029. After the upgrade:

- Journal revisions (operations, mutation admissions, component windows, VCI callbacks), translation records, captures (including their inspection cursors), reviews, approvals and candidates, Test Suite jobs and results, VCI manifests, comparisons and revisions, runtime capture plans and saved multiuser, Teamcenter, safety-evidence and composite reviews verify in the form they were written with (`CanonicalJson.Matches`, `CanonicalJson.Compatible`); new records use RFC 8785. Open operations recover as before, completed steps replay, and reading history needs nothing new.
- The earlier form is tried only when the content serializes differently in it; any other failure, a transient one included, keeps its own code.
- External resource keys and credential binding hashes keep the earlier form: stored records lock and compare these identities, and the binding hash is the vault's DPAPI entropy.
- A step that would bind an earlier hash to something new is refused with `CanonicalFormChanged`: a new approval, candidate or import from a translation review prepared before the upgrade, and a commit from a VCI preview made before it. Prepare a new review from the same capture, or preview the commit again.
- The worker accepts its own earlier form (ordinal-sorted compact Newtonsoft JSON) where it recomputes a value an earlier worker stored: an admission's observation and source hashes at reconcile, the open and upgrade receipts' source hashes, and a reserved component window's manifest and source snapshot at bind. Such an admission therefore reconciles as before instead of being held, and a window reserved before the upgrade can be resumed by a fresh Host; only its completion still refuses (`ComponentAcceptanceIncomplete`) when a source file name has U+0085, U+2028 or U+2029, which the earlier worker escaped.
- Retained evidence keeps the hashes it recorded and is not rewritten; each summary pins the build that produced it.

Domains add their own identity dimensions: watch rows bind exact instance storage/member components and case hash; VCI packages bind all companion files and observed profile; translations bind workbook/layout/key/culture/source text; Test Suite definitions bind original bytes, required scope and result provenance. None can derive an online address, active license, current program identity or native qualification from these shared records.

Its adapter callbacks and recovery tests do not close native AC-02/AC-03 qualification.
