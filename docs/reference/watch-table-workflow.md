# Preserving watch documents and durable native workflow

WT-04 additionally exposes `watch_table_generate` and `watch_table_prepare_authoring` for exact-instance diagnostic generation and complete creation/update review. The [authoring workflow](watch-table-authoring.md) documents source binding, absent destinations, scalar row additions, removals, reordering, multilingual comments and creation recovery. Each new mutation profile remains gated pending its own native lifecycle evidence; review is available in production.

Six further prepare tools cover the table and group lifecycle: create, rename and delete a watch table, create and rename a user group, and delete an empty one. They use the same apply, reopen and recovery path, with a group-scoped subtree target. See the [watch-table lifecycle guide](../guides/watch-tables.md).

The Host registers `watch_table_read`, `watch_table_prepare`, `watch_table_apply`, `watch_table_verify_reopen`, `watch_table_recover`, `watch_table_reconcile_recovery`, `watch_table_reconcile_interrupted`, and `engineering_operation_status`. This is the first scoped AC-02/AC-03 and WT-03/04/05 integration, not completion of those entire work packages. The catalog retains partial implementation and unverified broad qualification. All existing typed, component, HMI and runtime obligations remain required.

`WatchTableDocument` uses genuine V21 `WithDefaults` captures. It retains original bytes for a no-op and keeps opaque/native data during existing scalar, comment, row deletion, permutation and clone operations. Clones require a captured native row and refuse unqualified ID references. The parser bounds bytes, depth and rows and rejects DTDs, duplicate/aliased IDs, ambiguous containers and wrong profiles. Force documents accept the same row edits (fields `Name`, `Address`, `DisplayFormat`, `ForceValue`), but never a rename, `ModifyValue` or `ForceIntention`, and no edit at all while any row carries a `ForceIntention` other than false. Text whitespace, Unicode, line breaks and existing cultures are meaningful. Native document IDs and unknown payloads are not globally normalized. There is no fabricated Siemens XSD and no blanket native qualification for every offline editor operation. Scalar field reads and comment culture identities must be plain text: nested elements, comments and processing instructions are refused rather than flattened. The same culture check protects comment edits, language cloning and filtering. Opaque metadata outside those scalar contents remains preserved, and no-op capture still returns the original bytes. See the [offline preservation audit](../verification/watch-preservation-20261016.md). Content identity also includes XML comments and processing instructions before and after the root. The independent verifiers preserve those nodes and normalize only observed native ancestry, not similarly named elements inside opaque payloads. [Identity audit and compatibility evidence](../verification/watch-document-identity-20261016.md).

The first executable mutation is an existing Bool row's `ModifyValue`, explicitly `TRUE` or `FALSE`. It requires a scratch project created by this worker; its exact owned path can survive this worker's own native detach/reopen, but ownership is not inferred from a project name or transferred automatically to a new worker. This changes stored offline configuration only. It does not monitor, write a live value, arm modification, or force a PLC. Force-table document edits (`forceTable=true`) reuse this route under the qualification harness only; see [force-table document edits](../guides/watch-tables.md#force-table-document-edits).

Preparation exports an exact native target, typed row readback and peer manifests. It verifies captured byte/content hashes before editing, retains review/input artifacts and freezes target identity, worker epoch, binary/profile, physical project and resource effects in `EngineeringOperationStore`. The profile binds installed Base/Step7 API binaries. Applying requires the returned operation ID and exact reviewed plan SHA-256.

The dispatcher serializes all calls to its native bridge. A worker lease holds Siemens exclusive access continuously across reacquisition, checkpoint, dispatch and import. Durable resource acquisition precedes checkpoint intent; the archive is retained and hashed before dispatch intent. The worker independently reacquires the complete captured manifest and permits one import per lease. After import it checks intended XML, independent typed row values, consistency and peers, then saves. It retains ownership until the caller opens the saved project in a different native PID/epoch and verifies persistence. No compile or runtime result is inferred from watch consistency.

The worker compares the complete native identity and content again immediately before archive and import, permitting only a new observation receipt ID. Lost lease-acquisition or release replies retain an unknown durable owner even before a checkpoint exists. Returned apply readback is appended as immutable `dispatch.readback` evidence before validation, survives restart and remains retained through fresh reopen and recovery; a result that fails verification cannot release ownership. The [16 October boundary audit](../verification/ac0203-adapter-hardening-20261016.md) distinguishes these offline-tested hardening changes from the prior native qualification.

The bounded fixture manifest covers all watch/force documents and groups, exported blocks/types/tag tables of the selected PLC, configured hardware, active/reference/editing languages and exposed watch/force access assignments. Unexportable, protected or excessive data fails closed. Unexposed vendor payloads and unrelated product families are not a whole-project proof. Future broader write profiles need their own preservation providers and qualification.

Native observation is not replaced with caller-supplied identity strings. Reconnect, changed content, changed binary/profile, wrong owner or nonoffline state invalidates a prepared dispatch. Fresh reopen intentionally requires a new epoch while comparing the exact saved target and expected manifests. A saved project alone is not a durable-baseline oracle: the native trial discovered that a wholly blank comment row can disappear at fresh reopen. Retain that mismatch rather than removing it from comparisons; qualification fixtures now establish their baseline after reopening.

Recovery is explicit and never replays import. It reserves a distinct destination before native retrieval, verifies the archive, compares the restored baseline, then requires a further fresh recovered reopen and separate observation of the original. Their evidence is appended immutably to the journal before reconciliation releases reservations. A completed operation may be restored later only after reacquiring its original resource and new destination against other owners. Original successful/failed evidence stays retained.

Lost checkpoint or retrieval responses may leave no usable artifact receipt. `watch_table_reconcile_interrupted` observes the exact original in a fresh instance and can reconcile a baseline or reviewed outcome without native replay. A previously admitted destination must be explicitly verified absent/empty or retained as partial output, with bounded filesystem inspection and hashes. It does not claim a partial output was restored, delete it, or invent a missing checkpoint. Unknown, changed, locked or unsafe outputs keep reservations held.

The next dispatcher profiles implement edits to existing multilingual comments and row clone/reorder/delete, using genuine captured row grammar and complete XML/typed comparisons. Production preparation and dispatch remain gated to the qualified Bool edit. Only the isolated qualification harness explicitly enables the expanded profiles; synthetic lifecycle tests cannot promote them. The independent verifier requires the reviewed exact delta, unchanged peers, fresh reopen and verified restoration for each profile. Native IDs, unknown content and all existing cultures remain significant.

Qualification-only worker hooks cover before/after archive, import, save and retrieval. Harness response-loss hooks cover checkpoint, apply and retrieval replies. Managed child-process exits exercise persisted checkpoint/ready/dispatch/recovery boundaries and competing owners; these are not actual MCP Host or Siemens interruption qualification. The [current wave](../verification/recovery-expansion-wave-20261015.md) records the blocked native attempts and retained fixture requests.

All cooperating Hosts must use the same artifact root. Existing mutation routes now use shared resource-specific dispatch admission as described in [the shared substrate](engineering-operation-journal.md), with native qualification and historical-journal migration still open. Other independent tools/processes are not isolated by an OS store lock. Cross-host admission, retention/administration, complete queued cancellation/deadline behavior, every native interruption point, full watch lifecycle, access rules, populated force/remote/product/CPU profiles and broader restoration remain release obligations.

Tests and immutable native receipts are recorded in the [production watch wave](../verification/production-watch-wave-20261015.md). Standalone qualification helpers are evidence collectors; only the Host dispatcher and worker protocol constitute the production watch route.
