# Controlled local Git runner

On Windows, controlled commands enable `core.longpaths` only for that invocation. Working/control directories must remain below 260 UTF-16 characters, and the repository startup path through `.git/objects` must also remain below 260. Longer contained files and object paths are supported within the existing file/byte limits. Startup-bound violations refuse before initialization dispatch. Commands explicitly select the current directory’s `.git` and working tree, so unavailable child metadata cannot select an enclosing repository. [Regression evidence](../verification/git-paths-20261023.md).

The VCI-03 local process slice is implemented in [GitWorkspaceRunner.cs](../../src/TiaMcp.Core/VersionControl/GitWorkspaceRunner.cs), [GitProcess.cs](../../src/TiaMcp.Core/VersionControl/GitProcess.cs) and [GitWorkspaceModels.cs](../../src/TiaMcp.Core/VersionControl/GitWorkspaceModels.cs). It complements the [offline manifest/conflict model](vci-planning.md). It does not call Siemens or establish native VCI support. Shared durable callback integration is implemented. The [offline Host document workflow](vci-host-workflow.md) now exposes local review/commit/history/materialization and file-only durable callbacks. The [package Host workflow](vci-package-workflow.md) also reviews supplied mappings and three-way conflicts. Native mapping lifecycle, remote transfer and the native export-to-commit acceptance workflow remain open.

## Implemented operations

| Method | Result and enforced boundary |
| --- | --- |
| `InitializeAsync` | Initializes only a new, explicitly selected local directory, with a literal local branch, SHA-1 objects and an empty template. Existing directories are refused. |
| `InspectAsync` | Captures canonical repository path, symbolic HEAD reference, exact commit/tree, raw index/config SHA-256, bounded porcelain status and every regular working-file path/size/SHA-256, including ignored files. Rejects unsupported repository structures and unmerged index entries. |
| `DiffAsync`, `HistoryAsync`, `BranchesAsync` | Bounded local observation. Diff disables external drivers, textconv, automatic index refresh and rename inference; it checks the snapshot before and after. History uses the captured immutable commit. Empty unborn history/diff is explicit. Untracked files remain in the snapshot rather than being invented as a tracked diff. |
| `PrepareCommitAsync` | Binds the reviewed snapshot, explicit selected additions/updates/deletions, supplied author and message. Requires the index to match HEAD. Copies selected raw bytes into a private immutable plan; rejects a no-op, missing files, ambiguous paths and stale observations. |
| `CommitAsync` | Requires the reviewed plan hash and a fresh full snapshot. Reserves the repository/index, creates a private index from HEAD, writes only selected raw blobs without filters, preserves existing Git modes, creates a commit, and publishes its local branch with expected-old compare-and-swap. It then publishes the matching index and verifies HEAD/tree/index. Unselected working edits and untracked files remain outside the commit. |
| `UpdateBranchAsync` | Creates or updates an explicitly named local branch against an exact expected old object ID (or required absence). Refuses the current branch; ordinary commit publication owns that index/ref pair. |
| `MaterializeAsync` | Resolves only an exact commit object ID, checks the complete tree and writes raw blobs into a new separate directory. Verifies each Git blob ID, length, written SHA-256 and readback. Records Git file modes but does not reconstruct OS permissions. Leaves the original worktree/index/ref untouched. |

`GitCommitResult` binds the commit/tree/parent to the reviewed plan and exact Git executable hash/version. `GitRevisionResult` contains the immutable revision and raw-file manifest. Both explicitly retain `NativeQualified = false`. These receipts do not imply engineering acceptance, compilation, project reconstruction or checkpoint recovery.

## Process and repository policy

The constructor accepts one administrator-selected absolute Git executable path and pins its SHA-256. There is no caller command, shell, environment or arbitrary argument interface. Every launch uses `ProcessStartInfo.ArgumentList`, redirects all streams, closes stdin, clears inherited environment variables and disables Git prompts, credential helpers, network protocols, global/system configuration, replacement objects, hooks, fsmonitor and automatic maintenance. Stdout and stderr are drained concurrently with hard limits; cancellation, timeout and excessive output stop the process tree. The executable is rehashed before dispatch.

The current conservative repository profile accepts a normal SHA-1 repository on a local branch with the minimal `core` configuration emitted by `git init`. It rejects config includes, aliases, custom drivers, remotes and all unsupported config keys. It also rejects active hooks, working or indexed `.gitattributes`/`.gitmodules`, attributes in `.git/info`, alternate object stores, shallow/worktree/bare repositories, unfinished merge/rebase/cherry-pick/revert operations, non-HEAD symbolic refs, nonregular index/tree entries, assume-unchanged/skip-worktree index flags and Git metadata locks. Intent-to-add state is a dirty index. A `.sample` hook is inert and allowed. Ordinary attributes and additional benign configuration need an explicit preserving profile before admission; they are not silently ignored.

Paths are absolute and local for repository/control/destination selection. Windows UNC/device paths, linked/reparse ancestors, linked entries, relative traversal, alternate streams, device filenames, case/Unicode collisions and `.git`/short-name metadata aliases are refused. The control directory is new and disjoint from every selected repository/output. This process profile does not isolate malicious operating-system writers; the shared resource owner must prevent concurrent uncoordinated filesystem modification. Snapshot rechecks, index locks and ref compare-and-swap detect normal drift but are not a filesystem transaction.

Default/hard bounds are 20,000 working/index/revision files, 1 GiB total raw files, 16 MiB per file/stdout, 64 KiB stderr and 30 seconds per process (configurable to at most 120 seconds). Metadata traversal is capped at 100,000 entries. A process limit is not a whole-job deadline. Raw exports above the per-file bound need a separately reviewed streaming implementation. Preparation and revision export currently launch a process per selected blob; the retained 100-file fixture measures only that implemented scale, while the existing pure manifest test covers 1,000 packages.

## AC-03 journal integration

`IGitOperationJournal.RecordAsync` is mandatory. Its implementation must persist before returning. The runner provides `dispatchPrepared`, `candidateRecorded`, `publicationPrepared`, `verified` and conservative `outcomeUnknown` phases, with operation ID, exact repository root, expected HEAD, snapshot/index/config hashes, plan hash, candidate commit/tree and private-index or output resource path as applicable. Read-only calls do not dispatch mutations.

[`GitOperationBinding`](../../src/TiaMcp.Core/VersionControl/GitOperationBinding.cs) now freezes an exact init, commit, branch-CAS or materialize intent. Its hash binds operation, repository, fresh dispatch-control directory, Git executable, reviewed commit plan/snapshot, branch/expected prior ref and immutable revision/destination as applicable. Every mutating runner callback carries that binding hash. `BuildPlan` reserves the linked project plus disjoint repository, control storage and output directory, retains the binding artifact, and requires `git.callbacks`, `git.result` and caller-specified engineering gates.

[`EngineeringGitOperationJournal`](../../src/TiaMcp.Core/VersionControl/EngineeringGitOperationJournal.cs) consumes one exact shared-store `ready` revision after the caller acquires and checkpoints every resource. Construct it before the mutating runner; construction of the runner writes its fresh control directory, so that resource must already be admitted. Commit preparation can use a separate admitted inspection runner. The adapter permits one invocation per operation, flushes an ordered hash-linked callback record before returning, and invokes shared `Dispatch` with the supplied native reacquisition provider before Git writes. Candidate/publication records remain durable prerequisites. Unknown callbacks call shared `MarkUnknown`; a lost callback leaves the shared dispatch intent owned. `Complete` requires the verified callback and every explicit result/preservation gate; it does not invent native evidence or equate a Git commit with engineering acceptance.

Restart uses `ReadCallbacks` and `EngineeringOperationStore.Read` for diagnosis. An existing invocation directory, in-flight state or stale revision refuses construction for replay, even when failure happened between callback persistence and shared dispatch. Recovery belongs to the shared explicit reconciliation APIs. Genuine resource checkpoints, package provenance, result validation and native reacquisition remain Host responsibilities. File flushes, process-reopen checks and injected lost responses do not establish machine power-loss durability.

A failure before the pre-dispatch journal callback completes does not dispatch Git writes. After dispatch, a cancellation, ref race, lost response or recording failure returns `GitOutcomeUnknownException`, retaining the operation ID and candidate commit when known. The original reviewed plan cannot be blindly replayed after a moved HEAD. Private indexes and dangling Git objects are retained for reconciliation. A successful ref publication followed by interrupted index publication can leave the real index at the old tree; the shared recovery flow must reconcile HEAD, candidate tree, index and raw files before further work. Ref/index publication is explicitly not atomic.

The local operation reservation prevents cooperating runner instances from dispatching simultaneously. An abandoned reservation is refused and needs explicit shared recovery. Git revision materialization is an isolated raw-file recovery primitive; it does not restore TIA state, native mappings, uncommitted/untracked checkpoints, credentials, external libraries or an original branch in place.

## Reproduction and remaining qualification

The normal managed suite remains Git-independent. Real Git/process fixtures require explicit opt-in and a new fixture directory:

```powershell
dotnet run --project tests/TiaMcp.VersionControl.Tests/TiaMcp.VersionControl.Tests.csproj --artifacts-path artifacts/expansion-foundation-20261015/vci/build-final -- --git-executable 'C:\Program Files\Git\cmd\git.exe' --git-fixtures 'D:\03_Entwicklung\TIA_MCP\artifacts\expansion-foundation-20261015\vci\fixtures-final'
```

[GitRunnerChecks.cs](../../tests/TiaMcp.VersionControl.Tests/GitRunnerChecks.cs) covers raw BOM/CRLF/binary/Unicode bytes, exact-file commits, deletion, isolated revision recovery, stale plan/files/HEAD, staged and unmerged index refusal, executable customization, environment isolation, symbolic refs, branch compare-and-swap and races, foreign lock preservation, process output/timeout/cancellation, pre-dispatch journal failure and lost completion/readback reconciliation. Windows timeout/cancellation cases use a clearly marked slow executable fixture; they test process control, not Git version behavior. Real Git fixture commands are confined to newly created repositories beneath the supplied artifact directory. No repository initialization or mutation is performed against the development root.

The earlier validation receipt (`artifacts/expansion-foundation-20261015/vci/validation.json`) retains the original Git evidence. The production-foundation receipt (`artifacts/production-watch-20261015/vci/validation.json`) adds shared-journal integration: 74 pure checks, 25 existing Git/process groups and nine durable integration groups (108 distinct checks across the retained runs). Durable checks cover all four mutations, exact binding refusal, native-recheck failure before Git writes, missing completion gates, stale callback tampering, interruption before/after publication, fresh-process no-replay and reservation retention. Native observation/checkpoint fixtures are explicitly synthetic and make no native calls. Native VCI mapping through Host, actual project/workspace restore, package provenance acceptance, higher measured process scale, approved attribute/config breadth, remote/CI operations and every native VCI profile/workflow remain release obligations under the [VCI plan](../plans/expansion-plans/vci-and-git.md).
