# Test Suite style jobs and shared durable operations

This is the shared TS-03 integration contract. [TestSuiteStyleOperation](../../src/TiaMcp.Core/TestSuite/TestSuiteStyleOperation.cs) builds a style-only [EngineeringOperationPlan](../../src/TiaMcp.Core/EngineeringJobs/EngineeringOperationModels.cs) for [EngineeringOperationStore](../../src/TiaMcp.Core/EngineeringJobs/EngineeringOperationStore.cs). The [production Host integration](testsuite-production-jobs.md) now supplies complete review, durable queue preparation/status/stops/results and explicitly gated execution/recovery entry points. Native profiles remain disabled; there is no automatic worker loop, native cancellation or qualification claim. The retained store fixture (`artifacts/expansion-foundation-20261015/test-suite/fixtures-03-durable/receipt.json`) uses authored observations and artifacts; no Siemens operation was performed.

## Immutable admission inputs

The run plan must have no blockers and use `executionMode:style`. Application tests and system tests need their own simulator/endpoint resource plans; the style seam cannot admit them. The target binds exact captured identity, project file path, source/content hashes, session epoch, adapter/profile hashes and hardware/native identity. Every definition must belong to that target's captured project/source manifest.

The plan reserves `EngineeringResourceKey.ForPath("project", target.ProjectFilePath)`, using the same normalized machine-local key as other engineering domains. Its recovery strategy is `projectArchiveToNewLocation`. The worker must additionally hold its existing exclusive native-session access across reacquisition, durable intent and native invocation; the durable reservation alone is not a native mutex.

Inputs are the canonical complete run-plan JSON and a separately hashed [TestSuiteDefinitionBundle](../../src/TiaMcp.Core/TestSuite/TestSuiteDefinitionBundle.cs). `Capture(run, captures)` requires the exact reviewed definition closure, including dependencies and exclusions, compares every complete manifest and retains the immutable original bytes in required order. `Restore(run, bytes)` rechecks original lengths and `OriginalSha256` values against that review and refuses unknown fields, duplicate fields, reordered entries and noncanonical encodings. Opaque native definition bytes, encoding, comments and line endings remain unchanged.

`BuildPlan(run, target, runArtifact, definitionBundleArtifact, definitions)` now requires the verified bundle and binds both artifact hashes to their exact content. The shared store separately verifies the actual retained files; a correct claimed hash cannot admit an unrelated file. The prior four-argument builder was used only by `DurableChecks` in the audited source tree, and those callers now pass the verified bundle. A future native adapter must restore the retained bundle and reacquire the actual selected rules/scope before invocation. These checks establish artifact identity, not native grammar, effective scope or execution authorization.

The bundle admits up to the planner's 1,000 required definitions, at most 16 MiB per original, 32 MiB of aggregate originals and 64 MiB of encoded canonical JSON. Encoded-size accounting includes JSON escaping of base64 characters. The October 16 offline receipt (`artifacts/parallel-resume-20261016/testsuite/managed-02/provenance.json`) passes 233 checks, including 50 bundle checks and four added durable-boundary checks. Its bundle scale receipt (`artifacts/parallel-resume-20261016/testsuite/managed-02/definition-bundle-checks.json`) records persistence and reopen of 1,000 definitions. No native operation was performed for these checks.

Required probe names are `testsuite.product`, `testsuite.license`, `testsuite.styleService` and `testsuite.scope`. Each must be `observed`; absent, blocked, empty, failed and unknown remain distinct failures. Probe artifacts must identify the exact installation/profile/project. The shared target guard checks presence and captured hashes; it cannot establish that caller-authored probes represent actual product/license observations. Only the admitted native adapter can supply that evidence.

## Dispatch and recovery sequence

| Step | Shared durable action | Required Test Suite adapter behavior |
| --- | --- | --- |
| Prepare | `Prepare(plan, idempotencyKey)` | Retain frozen selected membership, run plan, original definitions, expected independent findings and bounded effects. Same key with another plan is a conflict. |
| Acquire | `Acquire(id, revision)` | Acquire the canonical project reservation and the worker's exclusive native access. Another unreconciled operation blocks this project. |
| Checkpoint intent | `BeginCheckpoint(id, revision, reacquire)` | Reacquire exact target/probes. Persist intent before save/archive because checkpoint creation can itself change the project. |
| Checkpoint retained | `Checkpoint(id, revision, artifacts)` | Retain the genuine archive and complete preservation manifest. An interrupted checkpoint is unknown until reconciled. |
| Execution intent | `Dispatch(id, revision, reacquire)` | Reacquire immediately before invocation; recheck input/checkpoint bytes. Only after the flushed intent returns may the admitted worker call the selected native executor once. |
| Collect/verify | Intent remains held | Persist the unmodified native result capture before normalization. Retain scope observations separately. Compile, compare unrelated content, save/fresh reopen and inspect cleanup. |
| Success | `RecordOutcome(id, revision, true, evidence)` | First call `SuccessfulEvidence` to recompute complete result/scope coverage and bind the canonical report hashes. Supply every required native verification gate. |
| Failure/lost response | `RecordOutcome(...false...)` / `MarkUnknown(...)` | Keep the reservation. A transport failure, restart, missing result or partial evidence cannot imply native nonexecution or automatic retry. |
| Recovery intent | `ReserveRecovery(id, revision, destinations)` | Revalidate retained selected-resource checkpoint hashes and reserve every distinct destination before invoking restore. Missing/corrupt checkpoints prevent admission. |
| Reconciliation | `Reconcile(id, revision, perResourceEvidence, recoveryEvidence)` | Independently observe every original resource and admitted recovery destination. Original-resource `unchanged` evidence alone cannot release a possibly partial recovered copy. The old dispatch must never be replayed. |

Revision arguments enforce compare-and-swap. A restarted worker may observe `checkpointIntent` or `dispatchIntent` even if the call never began. It must treat that ambiguity conservatively and call `MarkUnknown` or reconcile from independent observations. Elapsed time does not authorize stealing a reservation.

The shared store's `reconciled` state means resource disposition is known; it does not mean tests passed. A style assertion failure may have a completely reconciled project while the Test Suite result gate remains failed. Likewise, a valid native result cannot compensate for failed preservation, fresh reopen or cleanup.

## Required evidence and stops

The style plan requires `testsuite.results`, `testsuite.scope`, `testsuite.rawResults`, `project.compile`, `project.preservation`, `project.freshReopen` and `resource.cleanup`. Result and scope evidence references must identify the canonical validated reports. Other gates need independently observed native artifacts; the shared store proves file retention and identity, not the truth of their contents. A report's legacy `ScopeVerified` Boolean cannot override missing/ignored/unexpected effective scope in the separate scope report.

Fresh reopen creates a new native session epoch. Its verifier must compare the reopened exact project, source/content and definitions to the frozen preservation expectation and retain both session identities. It must not reuse the old operation to dispatch in the new epoch. Restoring to another location is a new explicitly reserved recovery target, never an implicit overwrite of the original. Each admitted destination needs `verifiedRestored`, `verifiedAbsent` or `retainedPartial` evidence before reconciliation releases ownership. A resource marked `restoredToNewLocation` specifically requires matching `verifiedRestored` destination evidence.

No inspected public native cancellation route is established. `Stop` is safe before checkpoint intent; a stop during checkpoint or execution requires observation/reconciliation. Cooperative stop-between-runs means no new operation is admitted after the request. A blocking native list/group call stays one dispatch; the bridge cannot claim it cancelled or split the call after it started. Application sets remain intact and require their later runtime admission.

`TestSuiteJobState` remains a presentation/transition model. It cannot release the shared reservation or replace its revision chain. `TestSuiteStyleJobs` now persists queue membership and stop requests and derives progress from the authoritative shared revisions. Actual product discovery, independently complete scope, the admitted native session composition, failure injection inside a real call, recovery to a genuine reopened archive and native clean/violating oracles remain TS-01/TS-Q01 prerequisites. The optional single-rule public API boundary compiles but is not loaded into the worker or enabled.

The offline seam covers store reopen, idempotency, project contention, reacquisition at both intent boundaries, unknown-outcome resource retention, replay refusal, reconciliation, stop before the next operation, missing-gate refusal and canonical result/scope binding. The 1,000-definition/100,000-message fixture validates the pure data pipeline only. Native application/system execution, actual provisioned CI, runtime/endpoint ownership and every existing release obligation remain open.
