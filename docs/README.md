## Evidence and status

A qualification claim passes through four places; the first three are in git.

1. **Feature catalog:** [`contracts/feature-catalog.v1.json`](../contracts/feature-catalog.v1.json)
   states each feature's implementation and qualification. A feature is `verified` only
   when every evidence record it cites has a passed summary (`scripts/test_contracts.py`).
2. **Curated summaries:** [`evidence/<evidence-id>.json`](../evidence/README.md), written by
   `scripts/curate_evidence.py`, keep the source commit, binary hashes, each raw report's
   SHA-256, completion and the MCP tools that answered.
3. **Release matrix:** [`plans/release-matrix.v1.json`](plans/release-matrix.v1.json),
   generated by `scripts/release_matrix.py` from the catalog and the
   [release ledger](plans/release-obligations-20261015.md), binds every feature ×
   acceptance-criterion cell to its evidence.
4. **Raw reports:** kept out of git, because they may contain local paths, process IDs or
   project content, in the main checkout's `artifacts/evidence/<evidence-id>/`.
   `scripts/audit_evidence_store.py` checks them against the summaries;
   [`evidence/raw-reports-lost.json`](../evidence/raw-reports-lost.json) lists the 84
   reports that were gone before the store existed. Native runs write their reports and
   logs under the main checkout's `artifacts/` too, never into a folder outside the project.

Every catalog evidence record is cited by a feature. Records no feature cites any more
move verbatim to a retired list: 38 old records in catalog 0.4.68
([list](history/catalog-evidence-retired-20261028.json)) and 53 superseded or doc-only
records in 0.4.69 ([list](history/catalog-evidence-retired-20261029.json)) and 23 replaced
or superseded records in 0.4.70 ([list](history/catalog-evidence-retired-20261029-reruns.json)); their
summaries stay in `evidence/`. Three records from before 24 October still cite
`artifacts/` paths directly; only unverified features cite them, and their files are
listed as lost. Prose records per run are under [verification](#verification).

## Maintaining these docs

When work lands, add its dated note at the top of the [status log](history/status-log.md),
update the counts in [STATUS](STATUS.md) and keep [TODO](TODO.md) to open work. Keep
usage in guides, API and scope details in reference, acceptance requirements in plans,
and observed results in verification. Preserve dated evidence when an outcome changes.
Curate native runs with `scripts/curate_evidence.py`, which stores their raw reports;
other native reports, frozen builds and release bundles stay under `artifacts/`.

This reorganization preserved the original document bytes (`artifacts/docs-reorganization-20261009/before/docs`)
and old-to-new path map (`artifacts/docs-reorganization-20261009/path-map.json`).
Older evidence manifests may name the former document paths; their originals
remain in that backup. Release bundles and native evidence were not rewritten.
