The live corpus covers Boolean logic, IF/ELSIF and CASE boundaries, signed arithmetic and widening conversions, nested UDTs, signed array bounds, Unicode source/text declarations, FC calls, two FB multi-instances, rising-edge/reset-dominant latch logic, native TON_TIME and CTU_INT, AWL/STL logic/arithmetic, and existing LAD/FBD symbolic operand substitution. Graphical assertions compare complete interfaces and network structures, allowing only the intended operand change. Call assertions require the exact caller/callee pair on one native edge.

Fixture manifests hold independently specified truth tables, numeric boundary values, scan-state sequences and timing expectations. Native import, compile, export or cross-reference success qualifies only those engineering operations on the recorded profile. `run_conformance.py --live --phase runtime` reports blocked because this harness has no runtime-vector executor yet; the installed PLCSIM environment also reproduces `ErrorLoadingDll (-21)` on power-on, including an empty owned instance. Neither obstacle is converted into a pass or a silently skipped runtime result.

`target_capabilities` keeps API availability, bridge implementation, arbitrary-target qualification and target blockers separate. The tested probes preserved observed metadata and one sampled native block export; this is not a full project binary-equivalence claim. An exposed attribute setter or native service does not bypass the prepared-change workflow or prove that a particular write payload is valid.

Software-unit identity, selected edits and recovery have the separate evidence recorded above; see [object-model qualification](../reference/object-model.md). The fourteen-fixture corpus itself uses the standard scope and does not qualify software/safety-unit routing. Native protected content, multilingual comment preservation, large projects, other CPU families/firmware, broad graphical wiring, additional TO/hardware families and VM execution remain separate qualification obligations.

Instance-DB call resolution now uses exact native instance/type edges when available. Its fallback requires a complete block identity index, an unnamespaced DB, a globally unique unnamespaced FB short name and the same canonical software scope. Namespace-qualified or ambiguous cases without an exact native relation remain explicit unresolved calls; a truncated index cannot establish name uniqueness. Scope parsing uses the shared canonical identity grammar, so user folders/devices named `blocks` do not collapse software-unit boundaries. These guards have focused pure regression cases. The original fourteen-fixture run predates this hardening; the subsequent read-only graph regression verified the standard FC/FB and multi-instance edges, without claiming native fallback or namespaced duplicate-member qualification.

Non-block reference keys also include a known canonical owner path and length-prefixed native identity components. Pure tests distinguish equal native member text under different namespaced owners and prevent delimiter collisions between component values. This hardening does not claim native duplicate-member fixture qualification.

The nested-data fixture revealed a normalization gap: parsed interfaces expose scalar starts for `Item.Enabled` and `Item.Meta.CountValue`, but not individual starts within `Item.Samples`. Original native XML is retained. Do not interpret array declaration/import success as normalized array-element initial-value support.

Earlier hardware/TO, safety XML roundtrip, restart recovery, write-conflict and simulation memory-card evidence remains documented in [verification history](verification.md). That history supports its own exact operations and profiles; the new catalog must not promote it to unrestricted engineering parity.

The final tested distribution uses Release binaries. An earlier integrated Debug build passed; refreshing its host afterward encountered Windows file locks held by existing MCP client processes. Those client processes were left running. Use the new bundle's configuration and reconnect the MCP client to load the final binaries, or stop the development client before rebuilding Debug.
