# OPC UA runtime qualification — 20 October 2026

This lane implements and tests an actual encrypted UA client against an actual local OPC Foundation SDK server with synthetic values. It does not connect to an industrial device, start TIA/PLCSIM, change device configuration or extend physical qualification.

Current development receipts are retained under `artifacts/opcua-runtime-wave4-20261020`. The initial compilation and smoke failures remain present. In particular, the healthy local fixture needed its machine DNS name in addition to `localhost` because the SDK's domain checker resolves the localhost alias. Production hostname validation was retained. Cancellation initially surfaced as a generic protocol failure because the SDK wraps the cancellation; the client now records the actual caller/deadline cancellation and preserves session invalidation.

The final focused `managed-06` run passed **333 checks** and `managed-06-oracle.json` rejected **12 altered-evidence controls**. It includes real encrypted connect/browse/read/close; exact signed/unsigned 64-bit extremes; Good/Bad/Uncertain and missing timestamps; arrays/structures; scalar ByteString versus Byte array; wrong pin/application URI/hostname/expired certificate; an alternate advertised certificate versus the actual secure-channel certificate; changed namespace/server-start identity; stale session; denied continuation release and in-flight browse cancellation; read cancellation; username denial and credential echo suppression; actual process exit 73 and new-owner recovery; four live sessions and capacity recovery; owned transport cleanup despite deleted, corrupt, colliding or valid-but-changed terminal records; and idle-publication failure followed by cleanup of another live client. The check count includes each observed admitted service; the trace length may vary with SDK setup reads.

The final focused `mcp-02` run passed **64 checks** through the actual Host MCP tools. It used the real current-user DPAPI credential CLI, checked that retirement refuses before another UA service, compared Host-returned loaded assembly hashes to the exact requested Host directory, and observed zero remaining server sessions after graceful Host disposal. Original Host/server process handles were waited to clean exits; the managed fixture birth matched the original parent observation. Runtime binary and qualification source hashes were equal before/after execution. Both final focused runs use an explicit `127.0.0.1` endpoint; the server checks its actual listener addresses before readiness and the Python qualifier independently checks its process's listening sockets.

Earlier `managed-04`/`managed-05` and `mcp-01` receipts remain development evidence. Their client connections were local, but the SDK binds DNS-name server endpoints to wildcard listeners. Inspection of the pinned SDK exposed this fixture boundary; the final fixture uses a literal loopback IP, which the SDK binds exclusively. Those earlier runs are not evidence of loopback-only listener containment.

The independent Python oracle does not import production conversion code. It checks original scalar values, types, encodings, ranks, namespace identities, status and timestamps, service order, continuation release and the complete final read-only service trace. Mutated copies round UInt64, upgrade Uncertain quality, fabricate a timestamp, change namespace identity, convert a Byte array to a scalar, change integer encoding, text, minimum DateTime or ByteString type, add Write, remove CloseSession, or reverse session activation order; all must fail. A second lane independently reproduced and rechecked the encoding/text/date/ByteString and final-audit controls. Original receipts remain unchanged.

The suite's crash worker deliberately exits without disposal using its own process; recovery observes a retained unknown outcome, rejects a fresh attempt until explicit abandonment, then opens a separately requested healthy session. Record fault tests mutate only their own test stores. The idle-publication fixture uses a test-only old last-used observation to trigger the real bounded idle worker; it does not claim a two-minute wall-clock soak. Continuation cancellation uses an entered server BrowseNext request. No operating-system resource exhaustion, volume filling or forced device process termination is involved.
