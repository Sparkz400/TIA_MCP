# Capture review and publication-failure checks — 18 October 2026

Baseline: `365f60f4ddea88ff74e784907526d8600f18cbf0`. This increment adds regression coverage and clarifies existing behavior. Production code, contracts, tool count and packaged Explorer are unchanged. RT-03 and the full 44-workstream goal remain open.

## Executed checks

The managed capture suite now blocks replacement of `head.json` with a real Windows file-sharing lock after the next segment has been written. The previous head bytes and pinned prefix remain intact; the orphan segment stays visible and is not adopted. Releasing the lock and calling finish again does not retry the failed publication. A separate changed-head case refuses to overwrite an externally changed head while the caller's previously pinned prefix remains readable. The Windows sharing-lock case is explicitly conditional on Windows; the changed-head and existing segment-collision cases run on all supported test platforms.

The real Host/loopback TLS harness now verifies malformed, missing and hash-changed saved reviews are refused before capture intent or target requests. An explicitly supplied review from an unrelated synthetic project remains a declared association with `programMatchVerified:false`. This is intentional: the current API does not resolve signal-to-declaration or executable identity. Removing the review after a successful capture does not alter the retained declaration or restart acquisition. Status, export and a later Host restart retain the review hash without accessing the target or requiring the original review file.

For worker-level storage failure, the harness waits for a committed live prefix and occupies the next segment filename. Publication fails, the worker terminates, and status exposes `RuntimeCaptureStorageFailure`, an interrupted prefix, an uncommitted tail and unknown loss. Repeat start, page and export preserve that prefix without network requests. After killing and restarting the Host, the same prefix/tail remain; the former process's in-memory failure code is not invented. The existing crash, TLS, credentials, session policy, cancellation, exact-integer and connection-reuse tests still run.
