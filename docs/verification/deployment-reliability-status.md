## Implemented

- `Test-TiaMcpEnvironment.ps1` distinguishes missing components, unreadable metadata, access-token uncertainty and untested functionality. Offline use does not require PLCSIM. Installation metadata never certifies a license or actual execution.
- `New-IsolatedBuild.ps1` copies and hashes source inputs into a unique tree, verifies they did not change during capture, builds/publishes there and records output hashes. Existing client binaries and other build outputs are left alone.
- `Package.ps1` consumes these recorded inputs/outputs, rejects changes since compilation, excludes Siemens binaries, verifies a complete hash manifest and produces a ZIP plus an external machine-specific MCP configuration. `-SkipBuild` requires an explicit recorded isolated build directory.
- Launcher and configuration checks cover overrides, immutable bundle contents, quoting, SSH host identity, bounded connection handling and separate artifact storage. The manifest establishes hash consistency, not a publisher signature.
- `qualify_deployment.py` tests the actual generated local/SSH command. `--engineering` explicitly creates a new owned scratch project, compiles, exports, verifies transferred artifact bytes and releases the session. Default checks do not start a simulator.
- `qualify_reliability.py` separates real host transport faults against a durable test worker from native TIA attachment/recovery observations. Unknown outcomes are terminal and not replayed.
- `project_index` serves immutable metadata pages with authenticated cursors, bounded cache size and lifetime, explicit completeness, conservative local invalidation and optional native recapture. See [index contract](../guides/project-index.md).
- VMware guest qualification checks the archive and manifest on the guest, records its actual machine model, then reports passed/blocked/failed stages. The dedicated exchange returns diagnostic JSON/logs; native projects and recovery archives stay on the engineering machine.
