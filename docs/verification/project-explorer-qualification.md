# Project explorer qualification — 8 October 2026

This is an implementation and scoped evidence record, not a claim that every TIA project, HMI family, graphical instruction, desktop host or physical topology is qualified. E0–E4 code is present; release gates below distinguish successful checks from pending integration.

## Delivered implementation

- E0: versioned snapshot/reference/edge/coverage and provider schemas, detached model store, independent fixtures and additive feature-catalog entries. Existing `project_index` remains compatible.
- E1: actual V21 engineering compositions including native empty groups, hardware items, PLCs, software units, block/type/tag groups and technology objects. Explicit virtual display folders. Bounded capture, child/search paging, details, evidence relationships, verify, release and artifact export.
- E2: virtualized browser tree, text/kind/scope filters, breadcrumbs, keyboard navigation, exact references, separately captured details, coverage/freshness and failure states. Portable HTML needs no network. MCP App resource and adapter activate only after protocol negotiation.
- E3: calls, instances, reads, writes, type/dependency and configured I/O evidence. Graphs retain unresolved endpoints, origin, locations and timestamps. Hardware details use existing inspection services; hardware ancestry does not establish wiring or physical topology.
- E4: HMI workstream provider integration and a thin adapter over the existing typed LAD/FBD reader; no duplicate HMI implementation or compiler. JSON/HTML snapshots, graph SVG/PNG with provenance manifests, hashed release assets, packaging and relocation checks.

Run instructions and API envelopes are in [project-explorer.md](../guides/project-explorer.md). The source entry is `ui/project-explorer/index.html`. The recorded native viewer is `artifacts/project-explorer/native-viewer.html`; open locally with a current browser. It is deliberately labelled historical when expired.

| Final detached cache combined search/children p95, 19 warm samples | 1k: 72.1 ms | 10k: 32.4 ms | 50k: 51.9 ms |

The final detached 50k fixture serializes to 9,729,476 bytes; test-process peak working set was 637,759,488 bytes, and detached cache construction took 5,489 ms (`artifacts/project-explorer-final2-model-tests.log`). Browser process-tree memory was sampled 148 times at approximately 50 ms: the 50k workload's largest observed sum was 923,017,216 bytes (shared pages may be counted more than once; this is not a certified continuous peak). Browser binding delivery is reported separately, including Playwright serialization overhead; it is not native transport. See `artifacts/project-explorer/browser-performance.json` for machine/browser versions, cold/warm method and all bytes/timings. Native fixture generation/compilation time is excluded from capture measurements. Other native qualification work was active during final runs; an earlier contended final-small run had cached MCP p95 237.1 ms (`artifacts/project-explorer-final-native.json`), above the 200 ms target. The complete-export run recorded 47.5 ms; this is not a contention-independent latency guarantee.

The same-bundle HMI fixture captured 31 nodes after 235 accounted visits in 18,675 ms; exact screen details took 15,550 ms and the relationship query 16,068 ms, each including fresh native provider work. These numbers are deliberately separate from cached tree queries and browser rendering. Its exported XML hash certifies those specific bytes; the provider does not claim a complete HMI revision. No HMI scripts executed. The first live browser-to-native trace, concurrent with native fixture work, observed a 13,133 ms initial 93-node capture and a later 593 ms verification recapture. All timings are preserved in its report; the table does not imply uniform latency under concurrent engineering load.

The large native tag fixture's initial snapshot was 1,679,317 bytes; its final observation-enriched JSON is 1,729,446 bytes and HTML 1,832,114 bytes. Largest cached query page was 417,490 bytes, within 512 KiB. Native relationship extraction took 5,877 ms. Fixture preparation/import/compile/save took 30,051 ms and is excluded from capture/query measurements. One initial oracle expected the wrong invalidation error code; the actual `ModelInvalidated` rejection was correct and retained in `project-explorer-native-large-tags-fixture.json`. The completed continuation reopened the exact saved fixture read-only without replaying the import.
