## Implementation and authority

`--addin-handoff` opts the long-running Host into the receiver. The default Host creates no endpoint or discovery file; diagnosis mode rejects this option. The service shares the selected artifacts root and acquires the existing handoff ownership lock. It never creates another Host, calls a native worker, attaches TIA or supplies a synthetic authority. Production begin/complete/cancel requests return `AddInEnrollmentUnavailable`. Status and retained receipt reads remain available, with producer authentication, live selection and native qualification false. A receiver startup/runtime failure makes the opted-in Host exit unsuccessfully.

Discovery is atomically published at `addin-handoffs/receiver.json`, with the Host OS process identity, user SID, random receiver/pipe identity, protocol and bounds. Graceful shutdown marks it stopped; a crash may leave a stale listening observation. Restart publishes a new identity and invalidates pending challenges. Discovery is a hint, not authentication: a native companion must verify the actual pipe server and retained Host process instance before sending data. The test client performs that OS check; the native companion is still unavailable.

Four precreated pipe instances limit concurrent connections. Each connection has one request and an absolute twenty-second deadline, including reads, authority waits, response delivery and waiting for the reader to close. The input frame permits the canonical base64 encoding of at most one MiB of original selection bytes plus 4,096 bytes of envelope overhead; responses are limited to two MiB. JSON has a four-level request depth limit and exact fields/types; duplicate fields, caller-supplied identity, unknown operations and arbitrary native forwarding refuse. `begin`, `complete`, `cancel`, `read` and `status` are the entire wire protocol. The existing lifecycle retains its separate pending, storage, request and monotonic challenge limits.

The pipe DACL grants full control only to the current Windows user and explicitly denies the network-logon SID. It is protected against inherited entries. The first pipe reserves the endpoint name before discovery. Connected-client identity comes from Windows, with a retained process handle, creation time, image path and matching Windows session; the receiver checks it again before dispatch and response. Peer exit or disconnect cancels in-flight admission. This does not authenticate a loaded Add-In. Receipt lookup grants no live authority and never invokes the enrollment callback.

The receiver holds response bytes until the client closes or the deadline expires: immediately calling Windows pipe `Disconnect()` can discard unread output. Completion publication remains durable before response; an unread/lost response never causes automatic acquisition or execution replay. Cancellation before admission and cancellation after consumption remain distinct; a consumed request cannot be revived.

Different-user, remote SMB and different-session/elevation clients were not executed; the actual installed ACL and same-session process behavior were inspected/tested, not a complete Windows security qualification.
