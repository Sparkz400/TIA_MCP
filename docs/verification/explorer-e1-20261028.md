The [27 October audit](release-matrix-audit-20261027.md#closest-to-closable-by-owner) left the eight
`project_model*` rows open. The default fixture had passed, but the E1 acceptance in the
[explorer plan](../plans/project-explorer-plan.md#e1--implement-hierarchy-and-structured-queries) had
not. E1 asks for independent expected trees that match roots, ancestry and all paged children, with two
PLCs, software units, nested/empty groups, namespace collisions, unsupported software containers and
budget exhaustion. These two runs close those rows.

Everything ran in owned TIA Portal V21 Update 3 instances and owned scratch projects; nothing touched a
user project, a PLC or PLCSIM.

## Runner changes

[`scripts/qualify_project_explorer.py`](../../scripts/qualify_project_explorer.py) already checked the
following:
- two PLC scopes;
- duplicate names across units (seeder);
- nested and empty groups with exact ancestry;
- child pages that partition the tree;
- a 12-item partial capture;
- details checked against `block_read` and `hardware_inspect`;
- refusals of session-mismatched, released and disconnected selections.

It now also:

- **compares the tree with independent reads.** For every captured PLC, the block, type, tag-table and
  group paths must equal `software_inspect`. Every device and device item must equal a paged
  `device_inventory`.
- **adds an unsupported software container.** `--second-cpu "CPU 1214C DC/DC/DC"` adds a PLC that
  exposes no `PlcUnitProvider`. Each PLC must show either a native unit group or explicit
  `softwareUnits` coverage with status `unsupported`, so an absent service is never shown as empty.
- **adds a namespace collision.** `--namespace-collision` runs the seeder's `add-alternate-namespace`
  step, so unit A holds `TiaMcp_IsEnabled` in two namespaces. Both must keep distinct exact identities.
- **calls `project_model` itself** with `action: status`, and requires it to name the captured snapshot
  and metadata revision.

[`scripts/qualify_project_explorer_relationships.py`](../../scripts/qualify_project_explorer_relationships.py)
now records its tool calls, so its runs can be curated. The audit had found that the 26/27 October
provider records list no passed tools.
