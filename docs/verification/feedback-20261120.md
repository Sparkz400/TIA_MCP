# Openness clients and UMAC project login: native runs, 20 November 2026

Debug builds of branch `claude/openness-slot-umac-open` (Host and Openness V21 worker, plus
`scripts/native/UmacProjectSeeder`), TIA Portal V21, owned headless Portals and owned scratch projects only. No user
Portal was attached to and no user project was opened. The report is under `artifacts/s0952` on the maintainer's
workstation (not committed). Probe: `scripts/probe_feedback_20261120.py`.

## Openness clients (`attachedSessions`, `waitForIdleSeconds`)

Host A started an owned Portal and created a scratch project in it (about 100 s of Openness calls); Host B observed
that Portal and attached to it.

| Check | Result |
| --- | --- |
| `tia_discover` from Host B, Host A idle | Host A's worker listed in `attachedSessions`: process name and path, `processRunning: true`, `isActive: false`, `accessLevel` `Modify, Published`, `trustAuthority` `None` |
| `tia_discover` while Host A creates the scratch | the same session with `isActive: true` |
| `tia_attach` `waitForIdleSeconds: 3` during that call | refused after 3 s with `OpennessClientBusy`, naming Host A's worker in `busyClients`; nothing attached |
| `tia_attach` `waitForIdleSeconds: 30` after the call | attached at once; `attachedSessions` lists Host A's worker (`isActive: false`, `utilizationSeconds` 96.6) |
| `tia_detach` of Host B | detached; Host A's owned Portal kept running for Host A |
| `waitForIdleSeconds: 61` | refused by the Host before any worker call |

Not covered: a client whose process has exited (`processRunning: false`), and how long a plain attach (without
`waitForIdleSeconds`) waits behind a busy client.

## UMAC project login (`project_open` with `umacCredential`)

The saved scratch was protected by `UmacProjectSeeder protect` (`ProjectBase.ProtectProject` with a project
administrator user; generated password on standard input). The right and a wrong password were stored with
`--credential-store create --stdin` in a dedicated test vault, both bound to the scratch's full path, the user and
`projectUser`. A fresh owned Portal was started before each open that followed a failure.

| Check | Result |
| --- | --- |
| `project_open` without a login | `EngineeringError`: TIA reports the project as protected and refuses the write mode |
| Right credential, read-write | opened (`readOnly: false`), `umac.loginRequested: true`, `loginRequests: 1`; `project_inventory` lists the PLC |
| Right credential, `readOnly: true` | opened as secondary (`readOnly: true`), one login request |
| Wrong password | `UmacLoginFailed` after exactly one login request; TIA's message calls the account deactivated |
| Right credential after the wrong one | opened, one login request: the account was not locked |
| Another user name with the right reference | `CredentialContextMismatch` from the Host, before the worker was called |
| Unprotected scratch with a credential bound to it | opened, `loginRequested: false`, `loginRequests: 0` |

Not covered: a global (UMC) user, and `UmacLoginRejected` (TIA did not ask a second time after the wrong password).
The password never appeared in a tool argument, a bridge frame or the report.
