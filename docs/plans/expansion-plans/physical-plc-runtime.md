### Identity and freshness

Use three distinct records: runtime endpoint/device observation, connection epoch, and optional engineering association. Endpoint identity includes adapter, canonical endpoint, observed peer certificate/application identity, device evidence with provenance, and family/firmware when actually observed. A certificate authenticates an endpoint under the selected trust policy; it does not prove a particular PLC program. Serial number is optional and never invented from configuration.

Each symbol binds to that observation and epoch. Web symbols preserve exact vendor spelling and representation; UA symbols preserve namespace URI, identifier kind/value and current metadata digest. Index-to-URI resolution and registered node handles are redone after reconnect. Firmware/namespace/type/certificate/device changes invalidate prior selection; permissions are rechecked. A node rename/type change is not an automatic remap.

Engineering association records saved review ID/source hash, exact PLC/instance/declaration selectors, online type/path evidence, asserted program identifier, independent verification source and time. Without an independently established executable identity route, `programMatchVerified` stays false even when every name/type matches. A changed or unobservable program invalidates verified association. Unassociated read-only measurements may still be retained with visible uncertainty; behavior tests and writes cannot silently inherit that uncertainty as acceptance.

### Acquisition, bounds and recovery

Proposed initial host limits (engineering choices, not Siemens limits): four sessions, one in-flight Web request per endpoint, 64 selected signals per capture, 100..60,000 ms requested polling interval, ten-second request deadline, 10,000 browse nodes, depth 16, 200 rows/256 KiB per MCP page. A capture ends at the first of its requested duration (maximum one hour), 100,000 samples or 64 MiB. Aggregate retained runtime data is capped at 512 MiB; refuse a new capture if capacity is unavailable rather than evict required evidence. Individual values/frames also require byte and depth limits. Capability and CPU limits may reduce every bound. Increasing limits requires measured load evidence, not a global constants edit alone.

The implemented Web polling path uses a synchronous buffer of at most 128 rows and less than 1 MiB, with no acquisition queue. A future decoupled acquisition channel must stay below 4,096 samples and 8 MiB. On sustained storage/backpressure exhaustion, terminate acquisition with an explicit gap/limit reason and retain its completed segments. Distinguish values dropped by this host (countable), server overflow/sequence gaps (sometimes only lower bounds), and unobserved PLC changes during polls/disconnection (unknown). Never report unknown loss as zero. A slow client page request cannot stall the acquisition loop indefinitely.

Record UTC receive time, monotonic elapsed request/arrival times, nullable source/server timestamps, clock identity, sequence, reconnect epoch, status and raw provider status. Missing/bad values are null plus status, never carried forward as good. Preserve 64-bit integers, special numeric/unsupported representations and type metadata without lossy double conversion. All samples remain non-atomic across signals unless a separately qualified mechanism establishes a narrower consistency claim.

Persist append-only bounded segments with sequence ranges and hashes, plus an atomically replaced manifest. Crash recovery verifies complete segments, exposes an incomplete tail and marks capture interrupted; it does not restart target activity. Never interpolate gaps. Export exact retained samples/metadata and readable summaries with partial/terminal reasons. Evolve trace ingestion compatibly: preserve v1 records, add an explicit subscription acquisition mode/version with per-sample quality and clock evidence, and refuse lossy conversions that would erase missing/uncertain samples.

Read-only reconnect is bounded and cancellable with backoff, same endpoint/trust/device checks and a new epoch. No credential guessing, silent certificate acceptance, TLS downgrade, alternate-host redirect or write replay. Web login/session tokens and UA subscription handles are not durable secrets in capture files. A restart retains evidence but requires explicit reconnect; server sessions whose close response was lost are recorded cleanup-unknown until expiry or independent reconciliation. Physical CPU cleanup must never power off, reset, restore or download anything.
