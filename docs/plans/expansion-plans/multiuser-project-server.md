# Multiuser and Project Server: identities, sessions and external outcomes

Baseline: `48cfa73d4ad4dcc4eca82d54c7e72c2e1a16067b`, 18 October 2026. Covers X05 / AC-21 in the [roadmap](api-coverage-and-roadmap.md), independently of [Teamcenter](teamcenter-gateway.md). The original design/feasibility baseline added no adapter or Host tool. The later MU-02 supplied review is recorded below; no Project Server connection or native session is implemented.

## Intended workflow

Inspect a selected configured server, its groups, projects, local sessions and reported locks. Review an exact project/session baseline before creating or opening a session. Prepare edits through the existing engineering owner and journal. Present save, mark/unmark, discard-close and commit as distinct actions. Retain the returned revision and independent server observations. After interruption, inspect the original operation; do not replay its create, commit or cleanup calls.

The user has no Siemens installation or server here. The [supplied observation workflow](../../reference/multiuser-observations.md) now implements strict input review, comparison, persistence, bounded pages and Host restart/release handling. Such records remain unverified declarations; they are never promoted to a native provider's observations. Neither these tools, a mock server nor the existing generic external-resource journal proves Project Server semantics. Native workflow and UI packages remain open.

## Identity and observation contract

Keep public configuration, observed authority, project selection and owned session separate. Record exact adapter/profile hashes and component versions, capture ID/time, Windows principal reference, owner process instance, worker session epoch, authority host/protocol/port, configured alias, group ancestry, project name and any independently exposed generation/revision. Never promote the alias or name to a stable server identity, silently normalize identifiers, or guess a GUID. An unresolved endpoint alias or project replacement blocks native preparation.

`ServerProjectInfo` retains `Parent`, `ProjectName` and `ServerAlias`; `LocalSessionInfo` retains `Parent`, `ProjectFileInfo` and `SessionId`. These are the established selectors, not proof against delete/recreate. Bind a session to its exact server project, creation mode, local path, baseline observation and owned worker. A project and global library with equal names remain different resources. Unknown properties remain explicitly unavailable, with the original diagnostic and coverage limits retained.

Mark observations retain exact object references, mark state, observation interval and known deleted-object omission. Do not join different snapshots by display path. Report stale/outdated, other-user marks, unrepresentable/deleted objects, incomplete enumeration and read failures separately. No supplied observation satisfies live freshness, authentication, mutation approval or the generic journal's trusted readback callback.

## Operation and recovery rules

Reuse [engineering operation ownership](../../reference/engineering-operation-journal.md) rather than creating another transaction manager. The existing external key hashes exact provider/authority/owner strings and reserves only within the configured artifact store. A future trusted Project Server provider must establish canonical identity and remote concurrency protection; key construction alone does neither. Reserve the local project/session and all affected external owners together. Cross-host conflicts remain a native qualification gate.

| Action family | Admission and outcome boundary |
| --- | --- |
| Inventory, lock and markings queries | Bounded selected endpoint only; no implicit creation, opening, marking or configuration edits. Query failure is unknown, not absent. Save observation scope and time; recheck immediately before mutation. |
| Configure connection, change host/port/protocol, delete connection | Separate configuration mutations. Freeze old/new public configuration, credential references and dependent owners; do not perform during discovery. |
| Add project; create/open local or server session | Freeze source tree/hash, exact destination, selected server/project and mode. Journal creation/open intent before the call. Reconcile both local outputs and remote session registration after loss; never delete an uncertain partial session automatically. |
| Save; mark/unmark | Preserve local baseline and exact ordered targets. Resolve all objects under the same native owner; obtain required remote admission. Verify local and remote effects independently. Save is not assumed to publish a server revision. |
| Close without commit | Show pending changes and discard consequence. Require explicit admitted intent and recoverable baseline; retain uncertain close state after loss. No automatic save/commit/discard substitution. |
| Commit | Freeze baseline, marks, preservation scope and comment; verify correct session mode and native ownership. Persist dispatch once. Bind returned revision and independent server readback to this operation, not merely the latest revision with a matching comment. |
| Delete local session from server | Separate destructive action with exact session identity and local/remote consequences established first. Never a retry or cleanup shortcut. |

A project archive restores only a new local copy. It does not undo a server revision, delete a registration or release another user's lock. Unknown commit outcome retains reservations until a trusted provider independently resolves every original resource and partial destination. If no supported query can establish the result, the operation remains unresolved; a supplied screenshot/string cannot clear it. Compensating publication is a separate reviewed operation, not rollback of history.
