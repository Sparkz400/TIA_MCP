### Conflicts, freshness and recovery

Compare the last verified baseline with **both** current native exports and current workspace package bytes; native green alone cannot prove freshness. Required outcomes are unchanged, project-only, workspace-only, both-changed, incomplete-package, missing-side, identity-collision, multiply-mapped-write and unknown. Same name/different GUID or object identity is a collision, not an update. A removed capture row is not proof of deletion. Deletion intent must distinguish missing companion, unmap, file removal, library-version cleanup and native-object deletion.

Cross-device reuse of one workspace file can exist; build a reverse index and allow only one explicitly selected exporting source for that package. Multiple export writers refuse. Both-side changes always produce a conflict packet retaining base/project/workspace versions; a chosen or merged result becomes a new immutable input and new preview, never an automatic overwrite. These rules implement the documented VCI package and shared-file constraints. [VCI basics](https://docs.tia.siemens.cloud/r/en-us/v21/using-tia-portal-version-control-interface/tia-portal-version-control-interface-basics).

Apply state machine: reserve idempotency/resources → acquire exclusive native access and filesystem gate → recheck all hashes/status/HEAD → save and checkpoint project plus affected libraries/files/settings → record dispatched call → perform one directed operation → enumerate actual complete effects → compile every affected eligible target → save/readback → fresh reopen → preservation audit → final receipt. Multi-object operations are journaled sequences, not transactions. Compilation failure retains outputs and checkpoint with failed status; lost response becomes `OutcomeUnknown`. Do not retry a dispatched mutation. Cancellation stops between calls; it does not claim to abort a blocking Siemens call.

Recovery retrieves archives into new project/library locations and materializes verified file checkpoints in a new workspace; originals and failed artifacts remain. Reconcile partial resource recovery explicitly. A Git revert does not restore in-memory TIA state, and a project archive does not restore Git HEAD/index/settings/external library state. Structured errors include `VciFormatUnsupported`, `VciPackageIncomplete`, `VciMappingCollision`, `VciConflict`, `PreviewStale`, `VciNativeRouteUnresolved`, `VciPolicyScopeTooBroad`, existing `OutcomeUnknown` and `RecoveryPartial`.

### External Git and CI

Use an executable allowlist and argument arrays; paths/ref IDs are data, not shell commands. Scope to an explicitly selected owned repository. Capture executable/version, repository config, HEAD/object format, index tree, working files and dirty/untracked states. Init creates only a selected new directory. Ignore build outputs, temporary native work, credentials and transient journals; include raw export packages, manifests, verified library locks and required `.vci` configuration. Archive checkpoints/binaries can live in a content-addressed artifact store with durable references. Test LF/CRLF/BOM and attributes explicitly; automatic conversion must not alter imported bytes.

Status/diff must not execute external diff/textconv drivers; ordinary operations must not run unreviewed hooks, filters, submodule commands or repository scripts. Configure controlled execution, inspect attributes/config and refuse unsupported executable customizations. Commit only the reviewed exact file set/index tree, with supplied local author identity and message; branch creation checks expected old ref. Report a local commit separately from engineering acceptance. Clone/fetch/push/remote changes, credentials, signing and external pull-request publication require their own explicit requested destination/actions and endpoint tests; this planning request does not authorize publishing. Resolve merges in a separate directory and rerun native engineering checks before acceptance.

CI stages: immutable revision checkout/materialization → package/schema/companion/identity checks → isolated project retrieval → supported object creation/mapping → reviewed imports → affected native compile/save/reopen → independent preservation and intended behavior tests → export and compare → signed or hashed provenance artifact. Runner prerequisites include licensed V21/update/products, Openness account, suitable Windows session, explicit native queue, separate PLCSIM lease for runtime tests and clean known fixture. Hosted generic Linux Git tests cannot qualify native engineering. Provenance binds Git commit/tree, source-file hashes, baseline project/archive, native application/API/compiler identities, adapter binaries, target/firmware/catalog profiles, changes/journals, exported results and applicable loadable artifact hashes. Do not promise bit-identical generated binaries without measuring native nondeterminism; record semantic and byte comparisons separately.

## 4. Three complete workflows

**A. First project export to Git (first useful delivery).** Select a supplied copied project and a new owned repository directory. Inspect exact object eligibility/formats and all mappings; select package/language/library policies and report every unsupported/unobserved object. Capture project/review/dependency baseline and file manifest. Prepare workspace creation and export with collision-free paths and cleanup off; checkpoint, apply, save/reopen and prove untouched engineering content. Verify complete packages and hashes, retain native status. Initialize the new repository, review ignores/attributes and exact staged files, commit locally. Receipt binds commit to export/project/binaries and explicit omitted coverage. Acceptance includes inspecting this committed revision after host/TIA shutdown without native startup. No remote push occurs.

**B. Conflicting edits on both sides.** Starting at a verified commit/project baseline, independently change one native object and its workspace package; include a language companion conflict. Fresh compare must report both changes with their original bytes, same identity and impact scope. A requested sync is refused without altering either side. Review a three-way resolution in a new directory; preserve complete companion set and selected library GUIDs. Validate package, prepare WorkspaceToProject against new hashes, checkpoint and apply in an isolated copy; compile, test intended behavior, compare unrelated content, reopen and recover the checkpoint. Export the accepted result and commit exactly those verified files. If compilation fails or the response is lost, retain failed/unknown state and recover; never convert a successful text merge into a pass.

**C. Restore selected revision into an isolated project.** Resolve an immutable commit ID and package manifest, not a moving branch. Materialize its raw files in a new directory, verify companions and provenance, retrieve the recorded baseline archive into a new project. Reconcile target identity using explicit copy lineage and exact relative scope; reject same-name unrelated identities. Recreate mappings using supported routes, create absent objects through each verified family importer, prepare explicit removals separately, then synchronize in dependency order. Compile, save, fresh reopen, compare expected revision scope and unrelated baseline content, run relevant behavior tests and checkpoint recovery. Produce a new acceptance receipt; do not overwrite the original project/workspace or reset its branch. Without a complete baseline/creation route, report partial reconstruction and leave the obligation open.
