## 4. Jobs, results, recovery and coverage

Job states: prepared → queued → admitted → dispatched/running → collecting → verifying → passed/failed/blocked/inconclusive/outcomeUnknown. Stop-request metadata is separate from terminal state. Before dispatch reserve job/idempotency identity, snapshot inputs and checkpoint required resources, then revalidate source, selected tests, scope and resource owner. Native calls remain serial in the owning worker. Poll host-persisted status while a synchronous Run blocks; do not send extra calls into that worker for fabricated progress. Report coarse phases and known completed subjobs; native step progress remains unavailable unless a public mechanism is verified.

Stop requests prevent the next independently dispatchable case or set. Do not split a dependency-bearing native set into independent cases to simulate cancellation. Once Run is dispatched, an MCP timeout or disconnected caller does not mean the PLC stopped. Mark `stopRequested=true`, `nativeCancellationSupported=false/unresolved`, continue collecting through the owning coordinator; lost worker/response means outcomeUnknown and no resource reuse until reconciliation. Never kill unknown TIA/simulator processes as cancellation. UI stop/background debug remains a separate paused UI workflow. Actual before-dispatch stop, between-case stop and in-flight unknown-outcome qualification are required even if no public cancel route exists.

Preserve the native results tree unchanged: state, counts, message hierarchy, path, text, native timestamps and their offset/Kind if available, plus host UTC and monotonic observation bounds. Do not add timezone certainty when native DateTime lacks it. Aggregate counts may repeat child counts; never sum recursively into invented assertion totals. Result identity binds exact run input, native profile and binary manifest; store partial collection and exception details separately. If a supported native log export becomes available, retain bytes/hash; do not scrape private project storage. A lossless JSON serialization of the public result is evidence, not a claimed proprietary raw log export.

Normalized test outcomes distinguish executed-pass, assertion-fail, native-error/inconclusive, blocked-before-dispatch, explicitly excluded/skipped, not-run-after-stop and outcome-unknown. Warning and Information remain raw states until validated per-message/result policy; no “non-error means pass” rule. JUnit export maps assertion failures to failure, execution errors/inconclusive/unknown to error, not-run/blocked to skipped **plus a machine gate that still fails required coverage**; include full JSON reference and properties. Optional SARIF-style style findings require exact resolvable locations; unresolved paths stay unresolved. Finding joins use project/revision/object identity, never name similarity.

Definition mutations checkpoint the complete project and affected libraries; save/reopen and recovered-project exports must equal independent expected content. Tests can create project logs or change dirty state; establish these effects per mode and retain exact allowed additions. Runtime test writes/reset/download are not undone by a project archive. For simulator modes retain complete pre/post registry and memory-card/program manifests and exact ownership receipts. External-mode restoration/reset is an explicit test-fixture contract; do not promise arbitrary runtime rollback. Physical endpoint cleanup needs independent verification of allowed test variables and machine state; missing cleanup leaves the resource quarantined from subsequent work.

Build a coverage crosswalk keyed by requirement × DUT/profile × stimulus × assertion × timing/reset semantics. Map native cases to the nine custom families (Boolean, arithmetic, branches, edges, latches, timers, counters, instances, arrays/UDTs) as supplemental coverage. Prove expected state/cycle behavior independently; similar names do not establish equivalent tests. Native style/application/system results never replace the frozen custom 65-case acceptance obligation. A deliberately duplicated assertion can validate the adapter, but schedule it once per backend/profile with its own recorded purpose.

## 5. Complete release-gate workflow

1. Integration owner freezes source, exact binaries, native project/archive, definitions/interface packages, coverage crosswalk and required gate list. Pure parser/schema/result tests run in isolated outputs. Missing product/license/endpoint is recorded blocked, not silently removed.
2. Native engineering owner admits the copied project. Revalidate exact target/definition scope, compile all affected PLC/HMI scopes and retain complete diagnostics. Run selected native style rules against the frozen scope, collect findings, verify project preservation/save/reopen. Finish that owner's engineering lifetime or explicitly transfer the same owned session to the runtime packet.
3. Acquire the **exclusive simulator window**. For Test Suite system-managed execution, grant combined engineering/runtime admission for Test Suite's internal compile/download; all other engineering/runtime work waits. Run the reviewed native cases/sets; collect results and verify its created-instance cleanup. External mode instead takes an explicit prequalified instance handoff, checks loaded program/reset policy, then returns or releases it with evidence. Never co-run the custom harness on that instance.
4. After verified release of the Test Suite runtime resources, execute the required custom corpus in its own qualified fixture/lifetime. Reuse accepted engineering evidence where source/profile identities permit; do not rerun the whole native engineering suite merely because another backend ran. The protected custom runtime profile remains unchanged.
5. In a separate endpoint lease, run native system tests against the supplied isolated OPC UA CPU with exact permitted effects. AC-16/UA engineering supplies target/program/model evidence; this gate does not automatically connect to production or lower security. Verify post-test endpoint state and cleanup.
6. Aggregate independent compile, style, application, system, custom, preservation/reopen/recovery and cleanup gates. Compare required versus actually executed coverage, including skipped/unknown results. Publish local JSON and CI views with immutable provenance; release remains blocked until all feasible obligations and final combined package acceptance close. Hosted CI needs its own actual provisioned-run receipt; no new general VM proof is demanded.

First complete useful workflow is **native compile + selected existing style rules → exact health findings + preserved project + recoverable CI report**. It needs no simulator and can finish before endpoint acquisition. Full delivery adds application/system pipelines and all feasible definition/profile operations; first workflow completion is not D06 acceptance.
