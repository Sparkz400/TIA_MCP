# SIMATIC AX trace route — additional feasibility audit

14 October 2026. This supplements [TD-01](bug-driven-trace-feasibility.md) and corrects the overly broad implication that native CLI acquisition has no documented route. The V21 Openness negative finding remains scoped to that API. **SIMATIC AX has a documented separate PLC trace CLI. It is not an implemented or qualified backend here, nor evidence of creating a persistent trace object inside a TIA project.**

## Authoritative route and boundaries

The inspected Siemens documentation is pinned to trace **2.8.1, November 2024**; it is not asserted to be the newest package. It describes native PLC jobs for S7-1500 firmware 2.6 or later, requires an open AX Code project, and warns that recording increases OB/task execution time. Eligibility, timing and overload effects must still be demonstrated on the selected device. [Tracing overview](https://docs.industrial-operations-x.siemens.cloud/r/en-us/ax/tracing-docs/2.8.1/tracing?contentId=Fy96HyUxq~OmdgolDfoW2w)

TIA tag-table symbols and quoted DB names are documented inputs. Arrays are incomplete, and an AX global variable wins a conflicting name. Therefore a TIA symbol-to-AX mapping requires explicit collision checks; captured TIA identity alone does not prove what AX will resolve. Namespace, optimized DB, nested multi-instance and IN_OUT compatibility remain unqualified for this route. [TIA Portal tags](https://docs.industrial-operations-x.siemens.cloud/r/en-us/ax/tracing-docs/2.8.1/tracing/signals/tia-portal-tags?contentId=dgQsuu1nFtPU56eosqNxNw)

Configurations are documented YAML, with a vendor JSON schema supplied at `.apax/packages/@ax/trace-<platform>/bin/simatic-trace-config-schema-v2.json`. This is a positive supported external configuration candidate, separate from `.ttcfgx`; it does not establish `.ttcfgx` generation. Vendor schema bytes/version and executable package identity must be retained before implementing a compatible generator. Supplementary Unicode characters are excluded by the documented format. [Configuration](https://docs.industrial-operations-x.siemens.cloud/r/en-us/ax/tracing-docs/2.8.1/configuration-file?contentId=qxrq9xkmkXAFBtw9ieT4sA)

**The decisive restriction for this TIA workflow: save triggers are explicitly unsupported on TIA-engineered PLCs in the inspected version.** A level condition must not be represented as a rising/falling edge, and a free-running AX recording must not be passed off as the requested trigger/pre/post capture. A separately reviewed untriggered acquisition could still be useful, but it changes diagnostic coverage. [Save triggers](https://docs.industrial-operations-x.siemens.cloud/r/en-us/ax/tracing-docs/2.8.1/tracing/save-triggers?contentId=0XRwsddEJ23pUh0RB7mCtA)

For an eligible AX-engineered target, sample reduction counts checkpoint occurrences while the save condition is evaluated every checkpoint. Trigger sample counting differs from an assumed pre + trigger + post formula: the triggering cycle is part of the post-window, and too few collected pre-samples shorten the result. Do not apply this AX-engineered behavior to a TIA target. [Frequency, inspected 2.7.2](https://docs.industrial-operations-x.siemens.cloud/r/en-us/ax/tracing-docs/2.7.2/configuration-file/frequency?contentId=V5WCkx2eept9GgTq8Ud2jQ), [sampling window, 2.8.1](https://docs.industrial-operations-x.siemens.cloud/r/en-us/ax/tracing-docs/2.8.1/tracing/save-triggers/sampling-window?contentId=nMg6n3OCgPVmFLjBtyxS7w)

## Lifecycle and readback matrix

| Stage | Documented route | Bridge/qualification and unresolved requirement |
| --- | --- | --- |
| Configure/install | `apax trace job install <configuration> -t <target>` | Public CLI documented; not executed or wrapped. `--force` overwrites and `--enable` combines installation/arming, so a future owned-job adapter must exclude both by default. |
| List/status | `apax trace job list -t <target>`; structured job information contains name and state | Does not establish full signal/settings readback. Input-file echo or successful install is insufficient. |
| Arm/stop | Separate `job enable` and `job disable` commands | Later admitted execution only; unknown outcomes must be reconciled before retry. No blanket disable or uninstall of user jobs. |
| Read | `job read`; `measurement read <name> <activation> <sample> -t <target>` | Job read can yield a different sample count than configured; measurement retrieval has distinct IDs and completeness semantics. |
| Delete | Separate documented uninstall/measurement-delete command families | No deletion adapter or execution. Ownership ledger and preservation proof required. |
| TIA project persistence | No route established in inspected AX documentation | Native TIA trace objects, `.ttcfgx` roundtrip, reopen and interoperability remain unknown; do not equate a PLC job with a TIA project trace. |

[Install](https://docs.industrial-operations-x.siemens.cloud/r/en-us/ax/tracing-docs/2.8.1/command-line-interface/job-commands/install?contentId=QnVsYZaRihjcmqHtpLDXZQ), [job read, inspected 2.7.2](https://docs.industrial-operations-x.siemens.cloud/r/en-us/ax/tracing-docs/2.7.2/command-line-interface/job-commands/read?contentId=ZRHr3~SeDV5gBhPhVTdelQ), [structured job fields](https://docs.industrial-operations-x.siemens.cloud/r/en-us/ax/tracing-docs/2.8.1/command-line-interface/output-formatting/schema-format/job-information-artifact?contentId=xAdtOphbbwN0dsDEooyOPA), [measurement read](https://docs.industrial-operations-x.siemens.cloud/r/en-us/ax/tracing-docs/2.8.1/command-line-interface/measurement-commands/read-measurement?contentId=ZpQy29p8ftHD1GWNYjRbtw).

The documented install error table rejects more than 16 signals, unresolved addresses, structures, missing/invalid AX debugging information and schema failures. This is a version-specific documented bound, not proof that every 16-signal configuration fits every CPU or that TIA-only projects need AX symbols in every route. The apparent debug-symbol/TIA-tag interaction needs package and target clarification. ## Measurement handling

AX JSON and YAML results share a documented structure; result artifacts group samples under data sets identified by job name and activation timestamp. CSV is explicitly outside that shared supported schema, so the existing explicit CSV mapping service must not claim AX dialect qualification. [Schema format](https://docs.industrial-operations-x.siemens.cloud/r/en-us/ax/tracing-docs/2.8.1/command-line-interface/output-formatting/schema-format?contentId=2bGUEbjkPTgQoUwCDuacaA), [result artifact](https://docs.industrial-operations-x.siemens.cloud/r/en-us/ax/tracing-docs/2.8.1/command-line-interface/output-formatting/schema-format/result-artifact?contentId=faZi0Vnha~jOMWCdxJIBKg), [CSV](https://docs.industrial-operations-x.siemens.cloud/r/en-us/ax/tracing-docs/2.8.1/command-line-interface/output-formatting/csv-format?contentId=YGdGobO~efthsGqzR3N_3Q)

Relative-time output is elapsed **nanoseconds** from job start; ordinary measurement timestamps identify actual sample times separately from the header's start time. The offline normalized importer/comparator now accepts explicit `ns` and preserves exact values, including a tested seven-nanosecond offset. This does not validate the vendor export dialect or acquisition accuracy. Sequence numbers are documented for job read/stream and would supply additional dropout evidence in a later qualified decoder. [Relative time](https://docs.industrial-operations-x.siemens.cloud/r/en-us/ax/tracing-docs/2.8.1/command-line-interface/output-formatting/tabular-format/relative-time?contentId=0USHE208vswktdMbt3eYnQ), [sequence numbers](https://docs.industrial-operations-x.siemens.cloud/r/en-us/ax/tracing-docs/2.8.1/command-line-interface/output-formatting/tabular-format/sequence-number?contentId=BGLrA519UL6ShQVYYuleYg)
