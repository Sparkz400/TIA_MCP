## 4. Proposed architecture and contracts

All names in this section are proposals, not current tools. Keep .NET 10 Host pure and native Siemens references in the existing V21 net48 worker. Host plans templates/documents using captured evidence; worker owns exact native resolution, read/export, per-target observations, changes and readback. Do not add a second transport, native lifetime manager or journal engine.

Proposed tools: `watch_tables` (paged inventory), `watch_table_read` (watch or force kind, ordered rows and artifact references), `watch_table_plan` (pure justified suggestions and template mapping), `watch_table_validate` (pure/reference comparison with explicitly identified fresh observations), `watch_table_export` (bounded native export), `watch_table_access_read` (exact owner/rules). Status/apply/restore reuse **`change_prepare/change_apply/change_status/change_restore`**. Proposed mutation kinds: `watch_table_create`, `watch_table_rename`, `watch_table_delete`, `watch_table_document_update`, `watch_table_group_edit`, `watch_table_access_set`, and distinct `force_table_document_update`. Copy/move and master-copy operations get explicit profiles, not hidden flags on ordinary import.

Use existing projectPath/plcPath/scopePath/objectPath identity vocabulary. Proposed additive kinds are `watchTable`, `forceTable`, `watchTableGroup`; canonical paths must be approved by AC-02 before implementation. Rows use table identity + source document hash + ordinal, not an invented persistent native GUID. Rename/move/retrieval re-resolves identities. Store symbolic spelling separately from resolved components; symbols may match case-insensitively while object paths remain case-sensitive. Never infer PLC ownership from an unqualified symbol.

Proposed contracts: `contracts/watch-table-artifact.v1.schema.json`, `watch-table-plan.v1.schema.json`, `watch-table-observation.v1.schema.json`, and `watch-table-change.v1.schema.json`. An artifact includes native document hash/length/version/export options, exact owner/profile, ordered rows (`comment|watch|force|opaque`), raw fragment references, cultures, display tokens, stored intention/value/trigger tokens and opaque-content hashes. Signal rows refer to existing diagnostic IDs and declaration evidence; `tableAddress` belongs in a separate observation with origin/time/revision and `symbolic|absolute|unresolved` status. Never populate the diagnostic schema's null onlineAddress field.

Each plan retains `resolvedRows`, `unresolvedSuggestions`, duplicate/alias warnings, full source review identity, deterministic selection order, reason/evidence for each inclusion, omitted count and truncation reason. Generated watch templates default to observation-only stored intentions and do not introduce ModifyValue/ForceValue values. Editing an existing table preserves all stored values/intents unless the preview explicitly changes them. Typed numeric text must preserve precision and culture; unknown enums/tokens are opaque and uneditable until profiled.

Initial engineering bounds (design assumptions, not Siemens limits): page size default 100/max 500, recursive inventory max 50,000 objects with depth/cancellation limits; artifact max 16 MiB, max 10,000 rows and bounded XML depth/text; 64 signals per diagnostic case as existing contract. Larger tables use separately bounded generation batches with stable continuation hashes, not silent expansion of diagnostic limits. Prove native supported limits per target; report preflight rejection/truncation explicitly. Deduplicate only when exact signal storage/member/type/address match; preserve intentionally repeated rows and comments using caller policy.

Prepare checks source/target revision, every affected table/group/rule hash, full target-family manifest and reference availability. The worker must add watch tables and assignments to freshness/preservation coverage; generic project timestamps are insufficient. Preview lists exact removals, order changes, name changes, opaque fragments carried through and access exposure. Checkpoint before first mutation; native calls are not an atomic transaction. Journal before/after each effect and keep unknown outcome after response loss; do not replay Import/Create/Delete automatically. `change_status` reconciles identity/content before any retry. `change_restore` retrieves checkpoint into a new owned directory and verifies complete manifests and assignments after reopen; document import alone is not a proven recovery substitute.

Reject DTD/entity expansion, external references, invalid namespace/encoding, duplicate IDs/objects, wrong table family, surplus imported objects, path traversal, oversized documents, malformed literal/format combinations, stale row ordinals and mixed-owner imports before native apply. Preserve unresolved names for diagnosis; default generation cannot turn them into fabricated addresses. Errors distinguish `UnsupportedPublicRoute`, `TargetUnavailable`, `PrerequisiteMissing`, `UnqualifiedProfile`, `AmbiguousTarget`, `StaleRevision`, `UnresolvedSignal`, `UnsupportedDocumentProfile`, `PreservationMismatch` and `OutcomeUnknown`; integrate with existing BridgeException conventions through the coordinator.

## 5. First complete workflow and independent oracle

1. User selects exact captured FB path and instance DB/member path in a saved project review. Example fixture has FB `Motor`, instances `MotorA` and `MotorB`, nested instance `LineA.Drive`, and explicit input `Enable`, output `Running`, state `Fault`, counter `Starts`. These are **future authored fixture names**, not observed project objects.
2. Reuse `diagnostic_plan`/signal selection to justify inputs, outputs, state, actual parameter bindings and I/O dependencies. Present unresolved aliases, indirect/TEMP operands, inaccessible declarations and missing instance contexts. A selected FC needs caller-argument mapping; it cannot borrow an FB-style storage identity.
3. Pure table planner maps captured resolved storage components to proposed symbolic expressions. For optimized DBs never derive byte offsets; absolute addresses require captured native address evidence, width/alignment/range checks and fresh layout identity. Retain original symbol quoting and namespace components.
4. Fresh native read-only observation confirms exact PLC/program/source identity, symbols, eligible table owner, row grammar and access rules. Any absent observation remains pending. Native acceptance of a symbolic row does not prove live readability.
5. Prepare named watch-table creation/document update, review precise rows/reasons/order/format/comments and peer preservation manifest, then use existing apply/checkpoint flow. Export and enumerate native rows; compare independently, compile the owning PLC where required and preserve baseline diagnostics.
6. Save, close exact owned lifetime, reopen freshly, compare every row and untouched object/rule. Exercise restore into separate directory and compare baseline after fresh reopen. Deliver native document plus explanations and source/target/hash manifests. Live monitoring is a distinct subsequent operation.

The expected-entry oracle must be authored separately from the planner/parser under test: fixture declaration/call/storage table maps exact owner, DB/member components, datatype, intended symbolic spelling, ordinal, display format and language comments. A reviewer records expected MotorA rows and explicit exclusion of MotorB/TEMP/ambiguous namespace candidates. Compute expected addresses only from independently captured native layout for nonoptimized fixtures. Compare both public typed row readback and independently parsed fresh native XML against this oracle. An export compared to its own generated input, or parser A compared only to itself, is insufficient. Snapshot complete peer tables, force table, access assignments, source blocks/tags and hardware; normalize only independently justified volatile export provenance, retaining original bytes.
