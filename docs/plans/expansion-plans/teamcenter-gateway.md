# Teamcenter Gateway: connection, cache, dataset and publication contracts

Baseline: `48cfa73d4ad4dcc4eca82d54c7e72c2e1a16067b`, 18 October 2026. Covers X09 / AC-21 in the [roadmap](api-coverage-and-roadmap.md). [Project Server](multiuser-project-server.md) is a separate adapter. This plan adds no connection, download, checkout, publication or native implementation.

## Intended workflow and current scope

Connect to an explicitly selected nonproduction authority with protected credentials or an owned SSO flow. Search exact project/library items; select a revision and dataset with visible metadata. Review cache conflicts before downloading or opening. Review checkout, save, new-item/new-revision, checkin and cancel-checkout separately. Retain all returned identities and independent outcomes, including uncertain partial operations.

Without Siemens, we can implement supplied metadata review and diff, byte-bound local source/cache manifests, strict schemas, durable reports, UI, failure-injection tests and existing-journal integration tests. These prove handling of supplied data and synthetic effects. They do not prove entitlement, server identity, lock ownership, remote outcome or native preservation. The [TC-02 supplied review](../../reference/teamcenter-observations.md) now implements metadata comparison and separately retained local-manifest bytes. Declared file hashes remain unverified; there is still no native Teamcenter adapter.

## Identity, credentials and local cache contract

Keep the authenticated authority and Teamcenter instance, principal/group/role, native connection epoch, item type/ID, revision ID, dataset type/name and any independently exposed dataset version together. A project and a global library are distinct. Item or dataset display names alone cannot identify resources; revision IDs are opaque values, not lexically ordered counters. Do not manufacture hidden UIDs or treat a supplied URL as authenticated authority.

Use protected credential references and the existing owner process. Session tokens, passwords and authentication headers must never enter requests retained as public reports, URLs, plans, logs or error payloads. Public diagnostics should record a local opaque connection ID and epoch, not a hash of secret material. SSO configuration is distinct from the authenticated session and cannot authorize subsequent calls by itself. Disconnect is owned-session lifecycle work, not checkin/cancel-checkout of datasets.

Bind the exact closed local source or cache tree, file hashes, physical paths, project/library host and native session. Retain observed cache/server versions and mismatch state independently. Never infer the destination from item name or allow traversal/reparse/hardlink aliases. Download may choose its path internally; establish and reserve its complete destination scope before dispatch or refuse the operation. A returned `FileInfo` is not permission to overwrite an arbitrary existing path or open another owner's project.

Supplied review data must identify its declared source and coverage and keep authentication/freshness/native flags false. Unknown, missing, denied, ambiguous and observed-empty remain distinct. Reports may compare exact declarations but cannot grant checkout ownership or settle a journal.

## Publication and recovery contract

Reuse the [existing operation journal and external observations](../../reference/engineering-operation-journal.md). A trusted Teamcenter provider must canonicalize and authenticate authority/owner identity before using `EngineeringResourceKey.ForExternal`; the shared key only reserves within one configured artifact store. Group/role/session changes invalidate prepared plans even when item names remain equal.

| Action | Required scope and unresolved outcome |
| --- | --- |
| Connect/SSO/disconnect | Exact owned connection with bounded cancellation; retain lifecycle errors without leaking secrets. No implicit browser launch during inventory, dataset cleanup or automatic reconnection-and-replay. |
| Search/custom metadata | Explicit endpoint, item type and bounded query/results. Preserve ambiguity, missing fields, coverage and errors. Do not assume undocumented pagination/filter semantics. |
| Download/open | Separate remote read, cache write and native-open effects. Retain immutable old cache/source; explicit overwrite choice. If path/effect cannot be determined beforehand, block dispatch. Lost reply requires cache/path and native owner reconciliation. |
| Checkout | Reserve exact dataset plus affected local owner; obtain fresh independent lock/version observation. Persist intent once and preserve actual result. Same username is insufficient proof this operation acquired the lock. |
| Save/SaveToItem | Freeze exact source, item/revision/dataset, cache option, custom metadata and preservation scope. Revalidate before dispatch; independently inspect local and external outcomes. |
| New item/revision | Freeze callback-supplied metadata and all local/external effects; validate returned actual identities against planned constraints. Server-assigned IDs require a proven, conservatively reserved parent scope before creation. Do not guess the result after reply loss. |
| Proxy-object variants | Preserve separate object/dependency relationships and metadata. Do not treat their effect set as identical to whole-project publication. API/member presence does not establish complete preservation. |
| Checkin/cancel checkout | Distinct reviewed mutation and one-use dispatch, each with fresh ownership/result evidence. Do not implement either as exception cleanup or assume cancellation restores content. |
| Combined Project Server/Teamcenter | Reserve both external owners and the local project/metadata/archive outputs. Journal each effect in order; reconcile both revisions independently. No blind replay, remote object deletion or local-file rollback of a committed revision. |

After a timeout, worker death or lost reply, retain original intent, diagnostics and reservations. Local restoration cannot reverse remote history. A visible desired state proves only what a qualified readback establishes; it must also bind the exact operation, identity and coverage. If independent outcome or lock queries are unavailable, keep the outcome unknown and mutation disabled. Any compensating publication or deletion needs its own reviewed, supported operation.
