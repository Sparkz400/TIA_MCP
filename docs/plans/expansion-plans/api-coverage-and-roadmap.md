### 4.3 Identity, freshness, effects and recovery

An engineering reference contains adapter/TIA product+update, session epoch, project path and native project identity where exposed, project/source snapshot hash, PLC hardware order number/FW/path, software scope/namespace, object kind/path and stable native ID where exposed. A declaration extends that with block identity, interface/member path and native source hash. An instance reference adds call-site evidence, instance DB/native type relation and nested multi-instance path. A runtime reference adds backend, exact endpoint/CPU identity, certificate pin/trust decision, online program identity and symbol/NodeId mapping evidence. IP/name equality alone does not establish any of these relationships.

For library/VCI/server workflows add library type/version GUID, file format+language and companion manifest, VCI mapping/workspace identity, or server/project/local-session/revision/markings. For UA use namespace URI + identifier type/value, retaining original namespace index/alias and raw bytes; for HMI retain identity v2. Where an API supplies no durable identity, say so and invalidate/re-resolve on reconnect, move, rename, import, compile, upgrade or changed composition.

Every prepare result includes immutable input artifact IDs/hashes, exact target/profile, base fingerprints over all touched and dependency resources, semantic intended effects, untouched-content scope, required compile/reopen/recovery gates and unresolved blockers. Acquire short native exclusive access, recheck freshness and prerequisites, then checkpoint all affected resources. `checkpointSave:true` retains its explicit unsaved-project-save meaning. For imports with unknown broad effects, checkpoint/verify the broader scope rather than guessing a narrow effect set.

Jobs use durable IDs and idempotency keys with states `prepared`, `queued`, `running`, `succeeded`, `failed`, `blocked`, `stopped`, `outcomeUnknown`, `recoveryRequired`. Persist intent before dispatch. Timeout/disconnect is not proof of cancellation; no automatic mutation replay. An unsupported cancellation request stops future admission and reports the still-running/unknown native operation. Reconcile via journal and independent native readback before another mutation. Never erase a failed original when a later copy/recovery passes.

Recovery is typed per resource: project archive to new directory/new owned TIA; global library checkpoint to new copy; external workspace immutable files restored as explicit new version; server/Teamcenter revision reconciled or compensating revision prepared. Do not label an external commit undone because a local archive was retrieved. Credential/certificate references record purpose, target and recovery lineage, with private material excluded from exports, logs and plans.

### 4.4 Bounds and actionable capability/error reporting

Reuse existing bounds where applicable: target metadata `maxItems` 1–2,000, 50,000-object uniqueness bound, fixed typed probes and explicit unknown coverage; existing artifact transfer ceilings; IPC 4/16 MiB limits. Domain budgets additionally bound input bytes, XML/ZIP depth and expansion, objects/edges, translation cells, trace signals/samples/duration, result bytes and retention. Defaults are versioned profiles, not universal Siemens limits. The current UA parser's 16 MiB input, depth 64, 20,000 nodes and 32 MiB report remain its existing contract; the Host wrapper must return artifacts instead of attempting a giant inline response.

Return both observed and required capability facts: installed assembly/schema identity; documented route; service observation owner/time/target; product/license status (`unknown` until independently observed); implemented operation profile; required gates and matching evidence; authorization/precondition blockers. Distinguish missing optional assembly, null service, empty collection, access denied, unsupported target and failed probe. An absent unprobed feature is `notEvaluated`, not unsupported.

Retain existing `UnsupportedCapability`, `StaleRevision`, `ProjectBusy`, `CompileFailed`, `RecoveryRequired`, ambiguity/protection and quota errors. Proposed precise details/codes include `OptionalProductMissing`, `LicenseUnavailable`, `DocumentationMetadataMismatch`, `FormatProfileUnknown`, `TargetProgramMismatch`, `IncompleteDependencyProof`, `BackendTimingUnsupported`, `ConfigurationReadbackUnavailable`, `ExternalCommitOutcomeUnknown`, `NativeOutcomeUnknown`, `AdmissionRequired` and `EvidenceScopeMismatch`. Include operation/target, retry safety, unresolved fields and smallest remedy; do not echo secrets or claim “available” merely because a native setter exists.

## 7. Native/protocol qualification design

### 7.1 Common gate protocol

Each new mutation profile needs the following independently assessed gates. Pure parser/fake tests remain a separate ledger. No native acceptance was executed while creating this plan.

1. **Freeze and admit.** Freeze source, exact binary/resource/profile hashes, public DLL/XSD identities, fixture/input/expected-result hashes and run selection. Record current grant and owned project/session/CPU lifetimes. A stale admission or PID is insufficient. Refuse if another session owns the resource or an earlier outcome is unresolved.
2. **Independent expected model.** Author desired objects/values/relationships/order/IDs and expected failures before running the code under test. Use independently authored native fixtures and raw vendor exports/manual observations. Do not validate generated payloads by regenerating them through the same implementation or use the same parser as the sole oracle. Any allowed normalization is narrow, justified and versioned; unknown IDs/order/whitespace/declarations remain significant.
3. **Before image and preconditions.** Retain all affected and declared untouched object exports/configuration plus complete original file/companion manifest where meaningful. Record existing compiler diagnostics, unsaved state, protection/access, source version and native identity. Missing baseline, inaccessible peer content or incomplete dependency proof blocks a claim of complete preservation.
4. **Prepare and exact apply.** Independently compare preview against desired effects; stale/ambiguity/license/protection/wrong-target refusals occur before native writes wherever possible. Checkpoint every affected resource. Verify intended creations/deletions/renames/values/relations and all unexpected generated companion effects; no “success” based solely on return value.
5. **Untouched content and compile.** Compare unaffected blocks/types/tags/HMI resources/library identities/hardware peers and unknown payload fragments, including full before/after inventories. Compile every affected eligible software/device; capture complete diagnostic trees, not only summary counts. Treat native Error or incomplete diagnostics as failure. For artifacts without a compiler, record `notApplicable` with documented reason and substitute explicit native consistency/readback checks; this is distinct from skipped compile.
6. **Save/fresh reopen.** Close only owned lifetimes with receipts, open the saved result in a new owned process, and repeat independent effect/preservation/identity checks. Reopening a handle in the same cached worker is insufficient. Project binary bytes may naturally change on supported save; compare native semantics with explicit normalizations and preserve original source trees separately.
7. **Checkpoint recovery.** Use actual bridge recovery into a new directory and new owned worker, compare complete intended baseline, then close/reopen recovered result again. For component workflows recover the **first import checkpoint**. Seeder/manual archive retrieval or retrieval without guarded `change_restore` cannot satisfy that tool's recovery gate.
8. **Failure/interruption.** Exercise selected real transport/worker failure boundaries: before checkpoint, after durable intent, during/after mutation, compile, save and response delivery. Record what actually dispatched/completed; unknown stays unknown until independently reconciled. No retry/replay; recover affected resources and prove unrelated sessions/projects unchanged. Stop requests allow the active uninterruptible operation/case to reach its supported boundary and admit no next case. Engineering stop acceptance does not qualify runtime stop.
9. **Behavior/acquisition/UI.** Engineering compile is not behavior. For runtime, compare independent expected values, quality, actual symbol/instance/program, timing and cleanup. For HMI/interactive Add-Ins, use actual native visual/runtime acceptance when promised. A browser fixture or synthetic trace does not establish native rendering/acquisition.
10. **Scale/compatibility.** Measure bytes, latency, memory, checkpoint cost, completeness and truncation at agreed profile budgets. Test unsupported CPUs/FW/options/formats/cultures/path cases as refusals. Bind evidence to exact target profiles and binary lineage; no blanket V21 label.

### 7.3 Worked diagnostic outcome and explicit feasibility

Hypothetical fixture roles, **not asserted real project symbols**: CPU A has `UnitLine::ConveyorFB`, calls for Conveyor 1 and Conveyor 2, a nested timer/interlock instance and a separate command/feedback writer. 3. Propose roles: enable, output command, feedback, interlock, sequence step, observable timer state and fault status; include writer input/state if needed to distinguish hypotheses. 4. Prepare watch table plus TracePlan with requested event (“output/feedback drops while enable remains true”), sampling task, duration/pre/post window, signal/resource budgets and rationale. Effective settings remain unknown until native readback. Instrumenting TEMP/indirect data is a separate reviewed program change with timing effects.
5. For a **proven** native backend: configure unique owned trace/job, independently read back exact signal mapping/type/task/sample reduction/trigger/window/resource limits, verify online program identity, then separately arm/capture/stop/retrieve. Preserve all prior traces/jobs/measurements. Unsupported settings fail before transfer. For AX 2.8.1, the recorded TIA save-trigger restriction blocks a requirement for triggered pre/post capture; untriggered recording is a separately reviewed outcome, not equivalent fulfillment.
6. Inject a known interlock pulse in an owned fixture and verify sampled event against an independent timing/sequence oracle. Include a short pulse that polling can miss and confirm the tool reports insufficient evidence, not a passing bug test. Distinguish no reproduced fault from “fixed.” Compare before/after only with explicit aligned event/time and changed-program provenance.
7. Result states confirmed/contradicted/unresolved **sample predictions** and timing uncertainty, competing explanations and next useful capture. Correlation alone is not proven cause. Reuse the resolved plan on another machine instance only with revalidated scope/storage/program/backend limits.
