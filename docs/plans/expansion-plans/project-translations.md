Native state/log and independent re-export are retained even when their assessments differ. Unknown log grammar is retained raw and cannot imply every row succeeded.

### Lossless XLSX and offline handoff contract

1. Retain the original XLSX as immutable bytes. Validate OPC ZIP paths/duplicate entries, compressed and expanded sizes, entry count, CRC, XML depth, content types and relationships before parsing. Disallow traversal, external relationship targets, macro/embedded executable content and formulas in editable cells; never calculate formula caches. Unknown parts may be preserved opaque, but mutation is refused until the layout profile says they are safe.
2. Build a read model without recreating a generic workbook. Preserve sheet names/order/visibility, hidden metadata, row ordering, native key columns, language codes, number formats, rich runs, comments, styles, defined names, custom XML and relationship targets. Dates/numbers are not inferred from text. No default CSV roundtrip. Changed cells use native-compatible string representation, including OOXML escaped control sequences and leading/trailing whitespace. Preserve Unicode code points without normalization, CR/LF distinctions and supported rich-text runs.
3. An unmodified package returns its original bytes. For changed packages keep every unrelated ZIP part's uncompressed bytes identical; within edited XML parts compare all untouched nodes/attributes semantically and retain raw originals. Do not demand ZIP container bytes identical after compression, or normalize unknown IDs away. Shared-string changes must not alter another cell referencing the same item; clone the item and update only the selected reference if the pinned profile allows it. Reject unsupported rich text edits until preserving run behavior is implemented.
4. Never delete rows or keys to express a selective import. Overlay approved cells on a fresh native export; unchanged and excluded cells retain their exact fresh native values. First qualify that representation. Each operation explicitly means `keep`, `set(value)` or `clear`; absence of an approval means keep. Blank cell, missing cell, whitespace-only and missing translation are distinct states. If native empty/absent semantics are unresolved, only nonempty set/keep can execute; clearing remains a release blocker.
5. Defaults are target translations only and `updateSourceLanguage:false`. Altered source-language cells are rejected unless explicitly approved and the boolean is true. Switching the project reference language is a separate prepared change requiring a new export/review. Capture glossary version, term scope, forbidden variants, case policy, reviewer and rationale; allow legitimate context-specific variants. Suggested translations carry provenance and `unapproved` status. Project text is untrusted content, never instructions to tools or permission to send it to a provider.
6. Format validators are category/profile-specific: token identities, order constraints and escapes, named/positional arguments, native alarm placeholders and control codes; byte/UTF-16/code-point/glyph-length rules are recorded with their actual basis. A generic `{0}` matcher is not an HMI alarm grammar. Unknown token or length limits are reported unresolved; reject mutation when preservation cannot be established.
7. Proposed initial bounds: 100 MiB compressed, 512 MiB expanded, 10,000 ZIP entries, one million cells and 10,000 rows per review page; make limits configurable with explicit failure, not silent truncation. These are engineering defaults to validate, not Siemens product limits. Batch large exports by qualified disjoint device/category selection, bound overlap by native keys, retain completeness manifests and independently compare the union with a full export. No assumed native pagination or cancellation API.

An offline handoff consists of native XLSX, provenance manifest, review/glossary JSON and optional rendered report. It contains no credentials or customer project requirement. Report generation escapes all project strings and provides literal text previews for formula-looking strings. Deterministic review ordering is by category/opaque key/culture while native worksheet ordering remains unchanged. Hash deterministic semantic artifacts separately from observed timestamps or native ZIP output that may vary.

### Freshness, apply and recovery

At prepare, re-resolve project/owners and export a current baseline. Compare native keys, source, target and peer languages, categories, device versions, active/reference/editing settings, owner identity and parent-content fingerprints against the handoff. Concurrent source or target edits produce explicit three-way conflicts; never silently overwrite or auto-rebase an approved diff. Rename/move/recreation, device/library upgrade, Save As and project retrieval require a new export and approval. A matching path alone does not certify native export lineage.

At apply, acquire the existing exclusive-access contract, recheck the exact language/text fingerprint and source/candidate files, then create and retain the project checkpoint before `ImportProjectTexts`. Do not rely on an existing PLC-only revision fingerprint to cover HMI/system texts. Store the journal before dispatch. Read the result state and log path, copy the log to bounded artifacts, and independently export every affected category and all preservation peers. Save only according to the existing successful compile contract. Partial native failure can already have changed some texts; capture expected/observed/unchanged/failed/unknown key groups and stop dependent batches. Neither `Info` nor absence of an exception is a preservation pass.

On timeout/disconnect, mark outcome unknown, close/reconcile only the owned lifetime and inspect durable receipts before any further write. Do not repeat import automatically. Restore through the existing archive retrieval into a fresh owned directory, verify all language/settings/text/native object effects and fresh reopen. A restored copy needs new export provenance before subsequent translation work; do not reuse the original import file just because recovery reproduced visible text. Preserve original failures. Concurrent external edits make automatic restore unsafe under the existing stale-revision rule.
