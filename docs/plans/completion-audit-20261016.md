## Closure order and definition of finished

1. **Green integration checkpoint:** close A01–A09, accept owner handoffs, freeze all intended source, pass the complete offline/build/boundary matrix, record remaining native gates. This is the first measurable deliverable.
2. **Finished current workflows:** GRAPH, translations and exact watch authoring, then OPC UA offline MCP and VCI. Qualify small exact profiles and integrate their usage/tests/evidence before expanding them. Keep Test Suite's provider blocker explicit.
3. **Existing engineering completion:** typed candidate engineering, component installation, clean HMI and channel/physical inventory profiles, including preservation/recovery/negative gates.
4. **Exclusive runtime acceptance:** prerequisites → actual requested stop → diagnostic remaining 17 → one new complete 65-case run; typed and HMI/runtime matrices remain separately tracked.
5. **Full breadth and composites:** finish remaining feasible roadmap families and resolve every feasibility residual. Acquire required products, licenses, schemas, vendor assets, servers, host applications and benches early.
6. **Release:** combined frozen evidence, hosted CI on the intended remote/ref, immutable bundle, install/rollback and final support/evidence matrix. Remote publication, branch protections, Dependabot, security settings and release metadata remain pending. Existing VM proof is retained; repeat only a genuinely new compatibility/deployment gate.

A task closes only when its promised user-visible path works, exact source/binary/profile identities are retained, applicable positive/negative/preservation/reopen/recovery/interruption/runtime gates pass, tests are reproducible through the declared runner, public contracts and docs match, and no owned outcome remains unknown. A blocked prerequisite is a concrete acquisition/experiment task, not a hidden completion. Build success, a prepared packet or a growing check count alone is insufficient.

No calendar estimate is justified until exact target/profile scope and external prerequisites are settled. Limit work in progress, finish the smallest complete workflow, and immediately feed its reviewed result back into the integration checkpoint.
