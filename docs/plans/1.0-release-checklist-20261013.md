# TIA MCP 1.0 release checklist — 13 October 2026

**Release scope update — 15 October 2026:** The user requires every feasible capability before 1.0. Read the [current release ledger](release-obligations-20261015.md) before scheduling work. Older wording that permits optional expansions, selected-only release scope or a reduced 1.0 is superseded. Missing prerequisites and unresolved feasibility remain release blockers; recorded passed/failed evidence and native/UI scheduling boundaries remain intact.

This is a dated release audit of the local workspace, current acceptance plans,
source gates, retained validation receipts and other local Codex session activity.
It supplements [the live TODO](../TODO.md) and [current status](../STATUS.md).
It does not change the promised scope or qualify an in-flight run. The companion
audit receipt (`artifacts/release-audit-20261013/audit.json`) records the
observation time, source hashes and checks performed for this review.

**Assessment: 1.0 is not ready.** The project has broad implementation and strong
scoped evidence, but runtime, several native mutation/recovery routes, target
prerequisites and final delivery acceptance remain incomplete. The first release
needs an explicit operation/profile/target contract. A narrower PLC-only or
read-only HMI release is permitted by the plans only when labeled explicitly;
this checklist does not silently choose that reduction.

## Explicit roadmap boundaries

catalog/HSP profiles, broader distributed I/O, typed motion/drive connections,
TO version profiles, changed safety logic, F-I/O configuration, Startdrive,

## Recommended completion order

1. Let the existing owner reach the typed capture's terminal/cleanup boundary and
   audit it; settle the advertised scope and external HMI/desktop prerequisites.
2. Use the existing native queue for component installation/recovery, limited
   remote-I/O lifecycle, additional typed builder cases and eligible HMI work.
3. Close all owned engineering work, resolve runtime isolation/preservation and
   requested-stop prerequisites, then run typed/component behavior and the full
   frozen corpus in the exclusive simulator window.
4. Complete advertised native interruption/compatibility/scale gates, reconcile
   the evidence matrix, and freeze/regress/CI/package the release candidate.

No credible completion percentage or calendar date follows from tool counts.
The critical path includes native preservation/runtime failures and unavailable
HMI/desktop prerequisites, so successful offline checks alone cannot finish 1.0.
